# files/Dropbox

A Dropbox account and its files as local placeholders. It uses Dropbox's HTTP API, so an app can browse and search Dropbox without the Files provider's local listing. There is no SDK: a handful of endpoints over `NSURLSession`, all Objective-C. The piece has no UI. The mirror is a remote fetch backend (`files/FileLoading/AGENTS.md`), which the app installs at launch with `installAsRemoteBackend`, before any open.

| File | Owns |
| --- | --- |
| `DropboxClient` | The account: PKCE sign-in in `ASWebAuthenticationSession`, the refresh token in the Keychain, the access token in memory, and the JSON call. It subclasses `HTTPTransferClient` (`files/HTTP/AGENTS.md`), which runs the streamed download and the ranged read. This class makes their requests and reads Dropbox's answers. All three share one failure ladder (`handleFailureStatus:…`): an expired token refreshes once, any other 401 unlinks, and a throttle waits and resends. |
| `DropboxMirror` | The account as local files: listing reconciliation, the sidecars, search and the path mapping. It subclasses `RemotePlaceholderStore` (`files/RemoteFiles/AGENTS.md`), which owns the placeholders, the directory index's storage, the streaming fetch, the ranged read and the download budget. This class names each placeholder's Dropbox `id` and reads Dropbox's answers. |
| `DropboxRules.h` | The decisions with no network or disk: PKCE, the wire encodings, entry reading, the version check, the index key. Tested. |

**The piece reads nothing of the app's.** The app passes in its Dropbox app key and its Keychain service when it makes the client. It passes the mirror's root directory, its index xattr, and its download budget when it makes the mirror. It keeps the one mirror its screens and its remote backend share. The error domain is `vibe-libs.dropbox`.

**The piece builds on both platforms.** AuthenticationServices and the Keychain exist on macOS too, and nothing here imports UIKit or AppKit. `ASPresentationAnchor` is the platform's window.

`DropboxTests` drive the client and the mirror over `DropboxStubProtocol`, an `NSURLProtocol` in the session's configuration, and a temp root (`DropboxMirrorTestCase` and its subclasses). The streaming tests also take HTTP's `HTTPStub` and the handle's fixture writers.

**TRAP: the content endpoints take their arguments in the `Dropbox-API-Arg` header, which must be ASCII** (`VibeDropboxAPIArgHeader`). A path holding "é" or "日本" is sent as `\uXXXX` escapes. Raw UTF-8 there fails every non-English filename with a 400.

**TRAP: `DropboxClientInternal.h` never redeclares `useSessionConfiguration:` or `retryDelayScale`.** Both come from the base's `HTTPTransferClientInternal.h`. A redeclaration that cannot see the base's gets an ivar of its own. It starts at 0, not 1, and every retry wait would read it.

## The account

**The app key is not a secret.** PKCE needs none, and Dropbox grants every app the `db-<key>://2/token` redirect without registration. So the redirect follows from the key, and the app registers no URL scheme. Scopes: `account_info.read files.metadata.read files.content.read`. An app that browses music outside its own app folder needs **Full Dropbox** access.

**The client never waits for connectivity**, whatever configuration it is given. A waiting request holds a materialization lane, so an offline request fails at once.

**The refresh token is one Keychain item, `AfterFirstUnlockThisDeviceOnly`.** A refresh must work under the lock screen while background playback downloads the next track. A backup restored on another phone signs in again. **TRAP: before first unlock the item reads as locked (`errSecInteractionNotAllowed`), not absent.** Read as absent, the whole session would run signed out. The client remembers the lock and reads again at the next use (`isLinked`, `accountID`, any call), at most once every `kAccountLoadRetryInterval`, and posts the account change when it lands. Nothing is deleted at launch, only on a real account change.

**TRAP: an app's Keychain service and index xattr name data a signed-in user already has.** A changed service signs the user out. A changed xattr orphans every listed folder's index. A nil service keeps the account in memory only, as the tests do.

**TRAP: an unsigned simulator build cannot reach the Keychain.** Every `SecItem` call answers `-34018` (`errSecMissingEntitlement`). Sign-in works for the session, but the refresh token is never saved, and the next launch is signed out. Sign the simulator build to test anything across a relaunch.

**A scope the app lacks answers 400 with plain text, not JSON**, naming the scope. The client logs that body, and a sign-in logs the scopes it was granted. A scope enabled in the App Console reaches only grants made after it, so sign in again.

**One refresh is in flight at a time.** It is the refresh claim, and every caller arriving during it is a waiter on it. `_accountGeneration` moves on every sign-in and sign-out, so a refresh or a 401 from the previous account can neither restore nor unlink the current one. **TRAP: a Keychain save checks its generation inside the Keychain lock**, which a delete also takes. Delete-then-add is two calls, and a sign-out between them left the signed-out account linked at the next launch. A late answer to the account-name call cannot stamp its name and id on the next account (`refreshAccountNameWithCompletion:`), and the mirror's directory is the id. A 401 `expired_access_token` refreshes once and retries. Any other 401, and a refresh answered 400 (`invalid_grant`, revoked on dropbox.com), unlinks. Unlinking posts `VibeDropboxAccountDidChangeNotification`. The mirror then prunes every other account's directory. Signing out attempts to revoke the grant with a live access token. It refreshes an expired token first. A failed network request can leave the remote grant active after local sign-out. A cancel's rules are the base's (`files/HTTP/AGENTS.md`).

**`warmUp` warms the account once** (off main). With an account it refreshes the access token, which lives in memory, so a launch's first request would otherwise refresh. It also sends each session one `files/download` naming no file, refused at once, to open the connection to `content.dropboxapi.com`. A session's connections are its own, and the download and its tail ride different sessions. This takes the refresh and two TLS handshakes off the first play. The app calls it once at launch, never on a foreground, and never before first unlock.

## The mirror

The root holds one directory per account, named by the account's id. Keep it out of backups and out of any folder the Files app shows. **The mirror is lazy: a Dropbox folder exists here only once something listed it.** So an app lists a folder before it shows or opens it, and before it opens a search hit. `hasListedDirectory:` says whether anything has listed one yet. A folder its parent's listing made carries only its path in its index. One listed itself carries its files. There is no full sync, and search is Dropbox's. **TRAP: a directory a reconcile deletes takes the cached indexes with it** (`reconcileDirectory:`). Kept, a folder that leaves Dropbox and comes back is made empty, still reads as listed, and its open plays nothing. **A folder made on the way to a search hit takes the hit's `path_display`**, never `path_lower`, or the app names it in lowercase.

- **A placeholder is a sparse file of the remote size and `server_modified` with no permissions.** How it is written is the store's (`files/RemoteFiles/AGENTS.md`). **Size plus mtime is the version.** Dropbox moves `server_modified` on every upload, and downloaded bytes take the mtime from their own response's `Dropbox-API-Result`, so the next listing sees them as current. A version that differs goes back to a placeholder, and a departed entry is deleted.
- **Only playable audio (`PlayableExtensions`) and playlist files (`.cue`, `.m3u`, `.m3u8`) are mirrored.** The playlists download with the listing, off the disk queue, since a folder's open reads its sheet and a tap on an M3U reads it at once. **TRAP: one download per sheet** (`_sidecarWaiters`, the claim). Two refreshes of one folder both find the sheet missing and share its part file. The first to finish would rename the other's half-written bytes into place, so a refresh that finds the sheet claimed waits on that download. The budget never counts a playlist file, so it is never sent back to a placeholder (`downloadsUnder:`).
- **TRAP: a name read back from disk is never sent as a Dropbox path.** A file URL's path comes back decomposed (NFD), while Dropbox keeps names as uploaded, usually composed, so a derived path misses every accented file. Each directory's index (the store's xattr) holds its own Dropbox path and each file's Dropbox `id`, keyed by `VibeDropboxIndexKey`. A download goes by `id:…`, which also survives a rename (`remoteTargetForURL:error:`). A relisting goes by the directory's recorded path.
- **TRAP: only the last component of a `path_display` is guaranteed its case.** So a component is matched case-insensitively against what is on disk (`VibeDropboxLocalName`) before one is made, and two spellings of one folder land in one directory. The match lists the directory rather than probing. On a case-insensitive volume an `lstat` of another spelling succeeds, and the URL would carry that spelling.
- **The fetch streams into a hidden part file**, and the progress poll reads the transfer's own written count. A row's loading bar is therefore a real percentage. The fetch, its stream and its tail window are the store's.
- **The part file's rules are `HTTPTransferClient`'s** (`files/HTTP/AGENTS.md`): made once, only appended to, resent from its last byte, pinned to its first response's version, and kept when the link ended the transfer. For Dropbox the version is the `Dropbox-API-Result` `rev`, and the size is its `size`. A download by `id` answers whatever version is current, so the pin stops two revs splicing into one file. A mismatch fails the transfer with `VibeDropboxErrorFileChanged`, and a length other than `size` with `VibeDropboxErrorAPI`. `keepsPartAfterError:` keeps the part for a cancel (how a stall lets a stream go) and for a connection lost past the resend bound. The stale sweep takes a kept part after a day. **TRAP: the stale-part sweep goes by ctime, never mtime.** The install dates a finished part to its version just before the rename, and a relisting between the two would delete it.
- **A Dropbox stream's tail is read by id, like its download.** The store installs the tail window only when both answers name the same rev (`files/RemoteFiles/AGENTS.md`). The tail read starts with the download, not after its first response. So a file that needs its tail to open opens from the head. Such files are an M4A with `moov` last, a FLAC with no length, an Ogg Vorbis file, an AIFF or CAF with a chunk after its audio, and an MP3 under Apple's decoder, whose last 128 bytes CoreAudio reads. A longer index-last M4A, or a tag larger than the window, waits for its download.
- **TagLib reads tags by range.** The rule and a streaming file's shortcut are the store's. A metadata scan parses a placeholder through TagLib reading `files/download` with a `Range` header, about three requests a file with its artwork. Playback and prefetch can download the whole file. Metadata also needs the whole file for CoreAudio formats outside `PlayableExtensions.tagParsed` (w64 and caf). A lost art rendition is read by the same rule (`PlaceholderFiles readsRemotePlaceholderByRange:`). One known gap: a FLAC whose STREAMINFO has no length parses with no duration, since the fallback that measures it opens the file.
- **Past the download budget the oldest downloads go back to placeholders** (the store's eviction). The budget counts the linked account's directory. The app chooses it, and may set `downloadBudget` at any time. A smaller budget applies at once and posts the new total as a download's landing does. Size and mtime are kept, so cached tags and waveforms still match. A player still reading an evicted file keeps its open descriptor. `removeDownloadsWithCompletion:` does the same to all of them.

A mirror directory is an app-container URL with no security scope. A relaunch can restore from the placeholders offline.
