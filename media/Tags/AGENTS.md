# media/Tags

TagLib's fields and embedded art bytes, read and written. It depends on `third_party/taglib`, on `audio/AudioTypes` for the format names, and on `core/Common` for the log macros. It holds `TagLibAudioFile`, the TagLib wrapper, in Objective-C++, and `VibeTagWriter`, the in-place write of a file's fields and cover (Writing, below). `NSString+CPPStrings`, which `media/Metadata` shares, turns TagLib's UTF-8 into a string with its embedded NULs kept. It came from Vibe. It reads no app's settings, strings, or types.

`media/Metadata`'s parse is its one reader. It reads the title, the artist, the audio properties, and every tag field from the wrapper's `TagLib::File` (`media/Metadata/AGENTS.md`, The tag fields). What it does with them, the cache, the scan, and the artwork, is `media/Metadata/AGENTS.md`.

## How an app uses it

**`TagLibAudioFile` opens a file the way `TagLib::FileRef` would.** It answers the parsed `TagLib::File` and its tag, or null when no parser takes the file. `fileTypeForTagLibFile` names the kind, the codec's name as `AudioFileFormat.h` defines it: AAC, ALAC, or FLAC in an MP4 reads AAC, ALAC, or FLAC. `tagLibFileCarriesID3v2` answers whether the tag is ID3v2, which MPEG, WAV, and AIFF carry, by the parser that took the file. `albumArtDataFromTagLibFile` answers the bytes of the picture the art read shows: the first front cover, else the first picture. `VibeEmbeddedPictures` lists every picture with bytes, and `VibeShownPicture` names the one that shows. The art read, the writer's picture read, and its removal share them, so they agree. **A picture with no bytes never shows.** So an MP4 whose first `covr` entry is empty shows its second, where it showed nothing before.

`audioMD5FromTagLibFile` answers a FLAC's audio MD5 from its STREAMINFO block, or nil for the zeros an encoder writes when it computed none. `bitsPerSampleFromTagLibFile` answers a lossless stream's bits per sample: FLAC, ALAC or FLAC in MP4, PCM or float WAV, and AIFF. It answers 0 for a lossy codec, whose sample entry may still name 16 bits. `VibeTagLibReadEmbeddedArt` opens a file for its art alone, with no audio properties. It answers NO for a failed read: no parser took the file, or TagLib threw. YES with nil art is a file that carries none. An app keeps the two apart, so a failed read is never mistaken for a file without art.

**The header is C++**, so only Objective-C++ and C++ can include it. A file that includes it also needs TagLib's header paths, which the template brings. An app that takes it builds C++ as C++17 or later, since TagLib's sources are C++17. **TRAP: an app that also takes `VibeLibsVorbis` or `VibeLibsDecode` lists this template after them**, as it would `VibeLibsTaglib`. `taglib/ogg` holds TagLib's own `vorbis/vorbisfile.h`, and the first search path wins (the template's comment).

**A read blocks, and an entered read cannot be cancelled.** Call it off main. A corrupt tag can make TagLib throw. `VibeTagLibReadEmbeddedArt` catches it. A caller of the constructor wraps its own reads in a `try`, as `media/Metadata`'s parse does, since an uncaught throw on a worker ends the process.

## Detection

**`TagLibAudioFile` stands in for `TagLib::FileRef`**, whose detection references every format parser TagLib has. `third_party/taglib` vendors only some. The order is FileRef's: the extension's parser, then `isValid()`, then a sniff of the content. The extension map is FileRef's, plus `wave`, `bwf`, and `qta`, a QuickTime container `MP4::File` parses. An `.ogg` or `.oga` holds Vorbis or Opus, told apart by a sniff. The content sniff tries MPEG last, since its sniff takes frame sync bytes inside other formats for MP3. An update of TagLib re-checks the map against `fileref.cpp`.

**TRAP: the MPEG, AIFF, and WAV parsers take another format's bytes as valid.** So the extension's parser alone would read a FLAC named `.mp3`, or an AIFF named `.wav`, with no tags and no audio properties. As FileRef does since TagLib #1490, an AIFF or WAV extension first asks its parser's `isSupported`. An MPEG extension, which has no signature, first looks for another container's after any ID3v2 tag. On a mismatch the content sniff decides, and its stream is rewound. When the sniff finds nothing, the extension's parser reads the file. A WAVE whose format is MPEG audio stays MPEG.

**INFO text reads as UTF-8 when it is valid UTF-8, and as Latin-1 otherwise.** INFO declares no charset, and TagLib 2.3.2 answers an empty string for text that is not UTF-8, so Latin-1 text from Windows tools read as nothing. The wrapper installs its own `RIFF::Info::StringHandler` before its first parse. TagLib keeps one handler for the process, so an app that installs its own replaces this one.

**TRAP: a refused parser leaves the stream anywhere, and RIFF reads from `tell()`.** The constructor rewinds before the sniff. Without it a WAV named `.m4a` parses with no tags.

**TRAP: no Ogg stream parses as FLAC.** TagLib's FLAC sniff takes a stream with `fLaC` near its start, which FLAC in Ogg carries in its first page. `audio/Decode` refuses that file at the parser open, so the wrapper refuses it too. An app that shows a parsed file as playable would otherwise show one that cannot play.

Without `readProperties`, no audio properties are parsed. The art read never uses them, and no format's validity depends on them.

## Reading by range

**With a `VibeTagByteRangeRead`, the wrapper reads the file's bytes through the caller's block instead of from disk.** The caller passes the file's length too. `media/Metadata` passes one for a remote placeholder, a file whose bytes are on a server, so its tags and art are read without downloading the song. The block runs on the reading thread and blocks.

`VibeRangedStream` fetches 64 KiB blocks, one request per run of missing blocks, and keeps them for the stream's life. The first read fetches up to 384 KiB, so nearby art costs no second request. Later requests follow the parser's reads. A tail read can therefore fetch the file's end alone. A server must honor ranges, or the reader the app passes must skip to the offset itself.

**TRAP: a failed or short fetch throws.** The parse's `try` turns it into a failed parse. Returning short would let TagLib build a tag from bytes that were never read.

## The debug listener

`VibeInstallTagLibDebugListener` routes TagLib's debug output to the log as warnings. TagLib's own listener writes to `std::cerr` unsynchronized, so two workers race on the stream. It is defined only where `NDEBUG` is not, since there `TagLib::debug()` is a no-op. An app calls it once, under the same condition.

## Writing

**`VibeTagWriter.h` writes a file's tag fields and cover in place.** `VibeTagLibWriteTags` sets or removes fields by TagLib's property-map name, and sets the cover from JPEG, PNG, GIF, BMP, TIFF, or WebP bytes, or removes it, in one save. Every write names its flush (Sync, below). `VibeTagLibReadFields` reads the fields back by the names they were written with. `VibeTagLibReadPictures` and `VibeTagLibWritePictures` read every picture as its tag stores it and put them back, for an exact undo. A `VibeTagPicture`'s `imageMIMEType` is its type from its bytes. `VibeTagLibAudioDigest` answers a digest of the audio alone, and `VibeTagLibAudioMatches` compares two files' audio directly. The header is plain Objective-C, so Swift and a `.m` call it. **A write blocks**, as a read does, so call it off main.

**`VibeTagFields.h` names the fields the writer takes**, and only those. `media/Metadata`'s parse reads every field by the same constants, and files its rarer ones under them, so a write and a read spell each field alike. Another name, such as `LYRICS`, `URL`, or `PICTURE`, fails with `InvalidField`, since TagLib's frame for it would be added again at each write. A field's values are a list. An empty list, or one of empty strings, removes it.

**Only the fields named change.** For ID3v2, MP4, and a Xiph comment, the writer removes the frames, atoms, or comments that hold each named field, then adds the new ones. Other fields, unknown frames and atoms, other pictures, and the audio stay as TagLib found them. APE, ID3v1, and INFO have no editor of their own, so the writer sets each one's whole property map with the edit applied. Those tags hold only what their maps name. It saves such a tag only when the edit changed it. TagLib reuses an ID3v2 tag's padding when the new tag fits.

**A field's other spellings go with it, so a removal sticks.** `media/Metadata`'s parse falls back to them. A write of `COMMENT` also clears `DESCRIPTION`. A write of `LABEL` clears `ORGANIZATION` and `PUBLISHER`, and a write of `ORIGINALDATE` clears `ORIGINALYEAR`. A write of a number or its total clears `TOTALTRACKS` or `TOTALDISCS`, and in the formats that fold the total into the number, a separate `TRACKTOTAL` or `DISCTOTAL`. That covers ID3v2's `TXXX` frames, MP4's freeform atoms, and APE items. **TRAP: the parse reads ID3v2's `TIT1`, which TagLib calls the work, as the grouping when `GRP1` is absent.** So a removed grouping also removes a `TIT1` the reader showed. When both frames are present, the removal is refused, since it would leave `TIT1` showing as the grouping.

**The write is in place and not atomic, so an app writes a copy and checks it.** It clones the file beside itself, writes the clone, reads it back with `VibeTagLibReadFields`, and compares the clone's audio with the original's, through `VibeTagLibAudioMatches` or each one's `VibeTagLibAudioDigest`. Then it swaps the clone in. A tag read-back cannot see a truncated tail, and the digest can. `AudioFileHandleReplaceTests`, in `audio/Decode`'s tests, shows that a handle open on the original reads the original to its end after either swap, `rename(2)` or `RENAME_SWAP`, in every decoder's open.

**The digest reads the file's bytes without TagLib.** It covers an MP3's frames between its tags, a FLAC's STREAMINFO and frames, a WAV's `fmt ` and `data` chunks, and an AIFF's `COMM` and `SSND` chunks. For an MP4 it covers each sound track's `stsd` and its samples, where the sample table's chunk offsets put them, so a chunk offset TagLib rewrote wrongly changes it. For Ogg it covers the identification and setup headers, then each audio page's flags, granule, and body, but not its number or CRC, which TagLib's repagination changes. It reads the file once, with `pread`. **TRAP: a plain WAV whose `data` chunk is 0 bytes, or 0xFFFFFFFF from a writer that never finished, and an MP4 sound track with no samples, as a fragmented MP4's is, hold no audio to check.** The digest answers that the audio is not found, where before this change it answered the digest of no audio. So damaged audio cannot pass a check.

**`VibeTagLibAudioMatches` walks each file as the digest does, and compares the two streams of bytes instead of hashing them.** Equal streams are equal digests, so it agrees with the digest on every file. It records each stream as spans of the file, merged where they touch, so an MP3, FLAC, WAV, or AIFF is a few spans. An MP4 adds two spans a chunk, and an Ogg three a page. Streams of two lengths differ before a byte is compared, so a cut tail costs no read. Otherwise it reads both with `pread` into two buffers of 1 MiB or the audio's length, whichever is less, uninitialized, uncached (`F_NOCACHE`), and stops at the first differing byte. Its memory is the spans, the two buffers, and the walk's 64 KiB window, whatever the files' size or volume. **TRAP: neither the digest nor the match maps the file.** A mapped file cut short while it is read raises SIGBUS, which ends the app, and where Foundation will not map, as on a network volume, it reads the whole file into memory. Each holds the file open and checks its size and modification time before and after. A short read or a change answers `ReadFailed`. The match answers `AudioDiffers` for different audio, `SameFile` when both paths name one file by its device and inode, and the digest's own errors. An allocation that fails answers `ReadFailed` too.

**A write goes through `VibeCheckedFileStream`, not TagLib's `FileStream`.** **TRAP: TagLib's `FileStream` ignores what `fwrite` answers, and loses the last flush's error in its destructor.** The MPEG, WAV, AIFF, and FLAC saves then return true once they start. So on a full disk a cover that grows the tag shifts the file, its tail is never written, and the save answers true. The checked stream writes with `pwrite` and records the first failed read, write, or truncate. It writes nothing after one. When a tag grows, it moves the tail from the end down, so the first write is the one past the end, and a full disk fails before any byte moves. After the save, it checks the file's size against the size its writes imply and flushes (Sync, below). Any failure answers `SaveFailed`. YES means every write, the size check, and the flush succeeded.

### Sync

**`VibeTagWriteSyncBarrier` is honored only on an APFS volume in the boot disk's container. Every other volume gets `F_FULLFSYNC`, whatever the caller asked.** A drive that ignores barriers still answers success, so a barrier on it would order nothing. `VibeVolumeOrdersBarriers` decides from `fstatfs` and `statfs("/")`: the file system is `apfs`, the volume is `MNT_LOCAL` and not `MNT_REMOVABLE`, and its device's whole disk, `disk3` for `/dev/disk3s5`, is the root's. That container is the boot SSD, which on a current Mac, iPhone, or iPad is Apple's own, and Apple says its SSDs support barriers. An external drive, a disk image, a network volume, and a second internal container get the full flush. A Mac booted from an external drive or a drive Apple did not make would be trusted wrongly, and nothing the library can read tells it so. `testABarrierTakesOnlyTheBootContainer` writes to an APFS disk image and sees the full flush.

- **Full, `F_FULLFSYNC`.** When YES returns, the file's bytes, and every write the drive took before them, are on permanent storage, if the drive honors the flush. A power loss after that keeps the write. It drains the drive's whole queue, which costs milliseconds a file.
- **Barrier, `F_BARRIERFSYNC`, where honored.** When YES returns, the file's bytes are with the drive, and the drive puts no later write on storage before them. They may still be in its cache. A power loss can lose the write, and then also loses any later write, such as the rename that swaps a written copy in. It cannot leave the rename on storage without the copy's bytes. So the copy-and-swap edit leaves the old file or the new one, never a new name over missing bytes. It does not say which one.
- **A volume that refuses the barrier gets the full flush, and one that refuses that gets `fsync`.** A refusal is `ENOTSUP`, `ENOTTY`, or `EINVAL`. `fsync` only hands the bytes to the drive, which may reorder them with a later rename. So after a power loss there, a swapped-in copy can hold stale bytes. Disk images of FAT32, ExFAT, HFS+, and APFS on macOS 27 accept both calls, so none takes the fallback.

**The cover is every front cover, or when a file has none, the one picture the art read shows, whatever its type.** A cover write takes the cover and adds one front cover, first in MP4. A removal takes the cover and adds nothing. **So each removal takes what shows, and the next one takes what then shows.** No picture is taken that never showed. **TRAP: "other" pictures are not taken as a group.** On a file of a back cover then an "other" picture, the back cover shows, so that is what a removal takes. Taking every "other" first took a picture the user never saw, and left the one they did. A file of ten booklet scans loses one page a removal, never ten. MP4 has no types, so its first entry with bytes is the cover, and each removal takes one entry. Pictures with no bytes are never taken, since they never show.

**An exact undo saves `VibeTagLibReadPictures` before the edit, and writes that snapshot back with `VibeTagLibWritePictures`.** The edit's own result cannot say what it took. The read answers every picture with bytes in the file's order as a `VibeTagPicture`: its bytes, its MIME string as stored, its type, its description, and FLAC's and Xiph's width, height, depth, and color count. It also answers the index of the one the art read shows. The write replaces every picture with the list, in order, and checks no signature, so a mislabeled picture goes back mislabeled. An "other" picture stays "other", and an MP4's untyped TIFF stays untyped. A picture's type runs from 0 to 20, ID3v2's numbering, which FLAC and Xiph share. MP4's is `Untyped`, which the other formats write as "other". Each picture holds 1 to 16,000,000 bytes, FLAC's block less its header, and all of them at most 250,000,000, under ID3v2's 256 MiB tag. A list past either fails before the file opens. An MP4 holds a picture only as `Untyped` or `FrontCover`, since its entries keep no type, and refuses any other type. **`VibeTagLibPicturesFit` answers the same checks without writing**, so an app can tell before an edit that a list it read could not go back, and need not copy the limits. It opens the file for reading only. A `VibeTagPicture` is a value: `isEqual:` and `hash` cover every field.

**What an undo does not put back:**

- An `APIC`'s text encoding. It is written as UTF-8, or UTF-16 in ID3v2.3.
- The pictures' places among an ID3v2 tag's other frames. They follow the others.
- A FLAC's picture blocks' places among its other blocks. TagLib writes them after its `APPLICATION` and `CUESHEET` blocks.
- A legacy Ogg `COVERART` field. TagLib reads it as a picture, and it comes back as `METADATA_BLOCK_PICTURE`.
- An MP4 `covr` entry's locale bytes, which TagLib writes as zero, and an unusual type code, which TagLib reads as the type its bytes sniff as, or as untyped.
- A picture with no bytes, which the read never lists, so the write drops it.

**`imageMIMEType` is a picture's type from its bytes' signature**, since taggers often name a PNG `image/jpeg`. Bytes with no known signature take the tag's own type in lower case, or MP4's typed one. A cover write refuses those, and `VibeTagLibWritePictures` takes them.

**A failure is an `NSError` in `VibeTagWriteErrorDomain`, and no C++ exception leaves the call.** The arguments are checked before the file opens. Then the file must open for writing, and a parser must take it. Every refusal below is decided before the first write, so NO leaves the file's bytes unchanged, except with `SaveFailed` or `TagLibThrew`. **TRAP: TagLib's MPEG parser takes any bytes as valid**, so the writer also refuses a file with no MPEG frame. Without it, a text file named `.mp3` gained a tag.

### What each format writes

| Format | Fields | Cover |
| --- | --- | --- |
| MP3 | ID3v2. An existing APE or ID3v1 tag takes the edit too, when it changes | `APIC` of type front cover |
| FLAC | the Vorbis comment block. A FLAC with ID3 tags is refused | a `PICTURE` block of type front cover |
| Ogg Vorbis and Opus | the Vorbis comment packet | `METADATA_BLOCK_PICTURE` of type front cover |
| MP4 and M4A | the `ilst` atoms. A field TagLib has no atom for is a `----:com.apple.iTunes:` atom | the first `covr` entry |
| WAV | the `ID3 ` chunk. An existing `LIST` `INFO` chunk takes the edit too, when it changes | `APIC` in the `ID3 ` chunk |
| AIFF | the `ID3 ` chunk | `APIC` in the `ID3 ` chunk |

**An ID3v2 tag keeps its version.** A 2.3 tag is written as 2.3, and 2.4 as 2.4. A file with no ID3v2 tag gets 2.4, and so does a 2.2 tag, which TagLib cannot write.

Every format holds every field in `VibeTagFields.h`, with these limits:

- **ID3v2.3 holds a date as a year, a day, or a minute, and the original date as a year.** It holds `YYYY`, `YYYY-MM-DD`, or `YYYY-MM-DDTHH:MM` in `TYER`, `TDAT`, and `TIME`, and the original year in `TORY`. Any other value fails with `UnsupportedValue`, since TagLib would cut it short.
- **TRAP: TagLib drops `TMOO` when it renders ID3v2.3.** So the writer puts a 2.3 tag's mood in `TXXX:MOOD`, as Picard does, and it reads back as `MOOD`.
- **MP4 holds the track and disc numbers and totals, the tempo, and the compilation flag as whole numbers from 0 to 65535.** The compilation flag is 0 or 1. Any other value, or more than one, fails with `UnsupportedValue`.
- **TRAP: ID3v2, MP4, APE, and INFO hold a total inside its number, as "3/12".** The writer folds `TRACKTOTAL` and `DISCTOTAL` into the number, keeping the half not named. A total with no number writes 0 as the number. ID3v1 takes the number alone, and the date's first four digits as its year. A Xiph comment keeps the total in a field of its own, unless its number already holds "3/12". `VibeTagLibReadFields` splits "3/12" in every format.
- **Several values are kept** by ID3v2, 2.3 included, a Xiph comment, MP4's text atoms, and APE. ID3v1 and INFO keep the first.
- **MP4's pictures have no type.** Its first `covr` entry with bytes is the cover, which setting replaces and removing removes.
- **A cover is 1 to 16,000,000 bytes of a whole JPEG, PNG, GIF, BMP, TIFF, or WebP, and its first bytes must be what its MIME type says** (`VibeTagCoverMIMETypes`). That is a JPEG's `FF D8 FF`, a PNG's signature, `GIF87a` or `GIF89a`, `BM`, `II*` or `MM*` with its NUL, or a RIFF whose form is `WEBP`. **Whole** means a download cut short is refused. Past any zeros at its end, a JPEG ends in `FF D9` and a PNG in its `IEND` chunk, each within 32 bytes, and a GIF's last byte is its trailer. A BMP's header size at offset 14 is 12, 40, 52, 56, 64, 108, or 124, and its declared size fits its bytes. A WebP's RIFF size plus 8 fits its bytes. A BMP or WebP has no end marker, so a tail of zeros where its bytes never arrived passes as pixels. The types `image/jpg`, `image/pjpeg`, `image/x-ms-bmp`, `image/x-bmp`, and `image/tif` are read as their usual names. Any other cover fails with `InvalidImage`. ID3v2's `APIC` and FLAC's and a Xiph comment's picture name a type by its MIME string, so they hold all six.
- **TRAP: MP4's `covr` types only JPEG, PNG, GIF, and BMP.** A new TIFF or WebP cover would be an untyped entry, which Apple's readers need not show, so an MP4 refuses either with `InvalidImage`. An MP4 that already held one gets it back through `VibeTagLibWritePictures`, above. **TRAP: FLAC's save drops a block of 16 MiB or more and still succeeds.** So the cap keeps a picture under it, and a Vorbis comment that would pass it is refused.
- **MP4's `GENRE` covers `©gen` and `gnre`**, the ID3v1 genre number, so a write replaces both.

**What the writer refuses rather than lose:**

- **A compressed or encrypted ID3v2 frame fails with `UnsupportedFrame`.** **TRAP: zlib is not built in**, so TagLib parses such a frame as unknown and writes it back as a plain frame holding compressed bytes. A compressed `APIC` could be neither replaced nor removed.
- **A frame TagLib would drop fails with `WouldLoseData`.** TagLib's parse marks these to be discarded at any save of the tag, the writer's or anyone's: ID3v2.3's `EQUA`, `RVAD`, `TIME`, `TRDA`, `TSIZ`, and `TDAT`, and ID3v2.2's `CRM`, `EQU`, `LNK`, `RVA`, `TIM`, `TSI`, and `TDA`. A `TDAT` or `TIME` it merged into the date is no loss, since the date holds it. Its ID3v2.3 render also drops ID3v2.4's `ASPI`, `EQU2`, `RVA2`, `SEEK`, `SIGN`, `TDRL`, `TDTG`, `TMOO`, `TPRO`, and `TSST`, so a 2.3 tag holding one refuses. A title edit of a 2.3 file with mp3gain's `RVAD` is refused. TagLib's own save drops the frame, which `testID3v23FramesTagLibDropsRefuse` shows.
- **TRAP: TagLib's ID3v2.3 render keeps every genre with an ID3v1 number, but only the first without one.** So a 2.3 tag of "Deep House" and "Tech House" refuses any write that keeps both.
- **TRAP: TagLib's MP4 save rewrites `ilst` from the items it parsed.** An item it could not parse, or a second item of one name, would be lost. The writer reads the file's `ilst` children itself (`VibeMP4ItemNames.h`), and refuses unless each is a parsed item.
- **TRAP: FLAC's save renders its ID3v2 tag as 2.4, and copies the ID3 tags' fields into a missing Vorbis comment**, so a removal would not stick. A FLAC with an ID3v2 or ID3v1 tag is refused.

**TRAP: TagLib reads the first tag that is not empty.** A new ID3v2 tag holding one field would hide every field of an MP3's ID3v1 or APE tag, or of a WAV's INFO chunk. So an ID3v2 tag the writer creates, or finds empty, first takes the fields the file reads today.

**TRAP: TagLib renders INFO text as UTF-8, though INFO is often Latin-1.** While a write runs, a `VibeInfoEncodingScope` on its thread makes the wrapper's string handler render each INFO value in the bytes it was read from. A new value renders as UTF-8. A cover-only write leaves the INFO chunk's bytes alone.

**TRAP: TagLib's WAV save rewrites a `bext` or `iXML` chunk at the file's end**, its bytes unchanged.

## Tests

`Tests/media/Tags/` holds the tests of the detection: the extension's parser first, then the content sniff, with an ID3v2 tag before a FLAC, and FLAC in Ogg refused. They write their own untagged files with AVFoundation and an MP3's frames. Misnamed files check the header before the extension's parser. A WAV written by hand checks how INFO text decodes. The tests of the parse over the wrapper are `media/Metadata`'s: each format's tags and facts, the art, the range read through a placeholder's backend, and the fuzz family. The minimal consumer tags a WAV with TagLib, reads its title back through the wrapper, and reads its picture's bytes through a byte-range reader.

`VibeTagWriterTests` writes each format's file from `Tests/Support`'s fixtures, with Ogg pages from `OggFixtures.h`, since no Apple encoder writes Ogg. Every field, several values, and the cover round trip in every format. So does each cover type in each format that holds it, read back with its type, replaced, and put back, and MP4 refuses TIFF and WebP. A cover cut short is refused. `imageMIMEType` finds the type from the bytes when the tag names it wrongly or not at all. Each removal takes what shows: a back cover before an "other" picture, a file icon before one, the first of two "other" pictures, a lone "other" picture as ffmpeg writes it, and MP4's untyped entries, each until nothing shows. A file of booklet scans loses only the page that showed. `VibeTagLibPicturesFit` answers as `VibeTagLibWritePictures` does on every refusal of its own, in every format. A picture with no bytes never shows. Every picture comes back as it was, after a replacement or a removal, in each format, and a list past the limits is refused before the open. A one-field write leaves every other field, a custom field, an MP3's private frame, a back cover, the audio's digest, and a FLAC's audio MD5.

Each refusal and failure leaves the file's bytes: a read-only file, a damaged file, a bad argument or cover, a write past the file size limit, and every case in the refusal list above. The digest follows an audio byte and ignores a growing tag. The match answers as the digest does on each of those files, and on a one-bit change, a cut tail, and two formats. It refuses one file named twice, and survives a file cut short while it reads, which SIGBUS ended when it was mapped. A WAV's empty or unfinished `data` chunk and an MP4 track with no samples are no audio. A barrier write round trips in every format, and a disk image gets the full flush. An INFO chunk keeps its Latin-1 bytes. `testMeasureTheSyncAndTheMatch` times 200 writes each way, and the digest against the match on 2 GiB FLAC and WAV files. `testMeasureSmallMatches` times 200 matches of a small FLAC. They run only with `TEST_RUNNER_VIBE_TAG_MEASURE=1`.

`Tests/Fuzz/` also fuzzes this piece by coverage, under sanitizers, through its `tags-*` targets ([Tests/Fuzz/AGENTS.md](../../Tests/Fuzz/AGENTS.md)).
