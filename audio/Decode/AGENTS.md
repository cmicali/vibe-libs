# audio/Decode

One opened audio file, read as PCM. It holds `AudioFileHandle`, the file handle, with its MPEG and stream decodes and its read-ahead seam. It came from Vibe. It depends on `core/Common`, on `files/FileLoading` for a stream's and a read-ahead's bytes, and on the four decoders it hosts: `third_party/dr_mp3`, `dr_flac`, `dr_wav`, and `vorbis`. Its surface is `AVAudioFile`'s: the file's facts, a cursor in file frames, and reads into a PCM buffer. It also writes, through an `ExtAudioFile`, so an app's converter and its test fixtures share the class. It reads no app's settings, strings, or types.

`audio/Player`, `waveform/WaveformLoading`'s loader, and `media/Metadata`'s CoreAudio fallback each open one, and so may an app's own code. What a player does with a handle, its voices, its fades, and its deadline, is `audio/Player/AGENTS.md`. `docs/audio-quality.md` in Vibe has the measurements behind each decoder choice.

| File | Owns |
| --- | --- |
| `AudioFileHandle` | the parser, codec, and descriptor lifetime, the immutable facts, checked seeks, reads, and writes. It owns the one guarded, extension-hinted CoreAudio open (`openParserWithError:`), which a read reaches for a file none of the handle's decoders takes, and which a metadata fallback opens alone (`initParserForReading:`). It reads a file still streaming, and a file on a network mount through its read-ahead (below) |
| `AudioFileHandle+MPEG.m` | dr_mp3's decode: the open, which frames the stream itself, the walk that indexes its frames, a headerless stream's estimated count and its settle, the seek, the reads, and the packet decode |
| `AudioFileHandle+Stream.m` | dr_flac's, dr_wav's, and libvorbis's decode: which of the handle's decoders takes the file, dr_mp3 included, the opens, the close, and the reads. The byte reads they pass the decoders stay in `AudioFileHandle.m` |
| `AudioFileHandleInternal.h` | the private header the three share: the ivars the decodes read, the core's reads and waits they call, and the decodes' methods the core calls |
| `AudioFileHandle+Debug` | the read-ahead's test seam (below) |
| `TailWindowMath.h` | the bytes each format's open reads at a file's end, with room: the tail window a stream fetches beside its download. `files/RemoteFiles`' placeholder store sizes each stream's window by it (`VibeAudioFileTailWindowBytes`) |

The opener an app passes `files/FileLoading`'s coordinator makes a handle. The handle adopts `ServedFileHandle`, so the loader never names its class.

## The decoders

- **MPEG files (MP1, MP2, MP3) are decoded by dr_mp3**, on both platforms, with no choice. Apple's MPEG decoder offers only 16-bit integer output on arm64, which rounds without dither and clips a master's overs. Its x86_64 build outputs float32 and still clips them. `decoderName` names the decoder.
- **FLAC files are decoded by dr_flac**, with no choice. Its output is Apple's bit for bit at under half the CPU, it seeks without scanning from the start, and it plays legal FLACs Apple's codec refuses. dr_flac answers the file's facts too. CoreAudio's parser opens a FLAC only in a metadata fallback.
- **WAV, W64, RF64, and AIFF files are decoded by dr_wav** the same way, when they hold a coding it decodes. A coding it lacks, such as GSM, stays Apple's. MPEG in a WAV is the exception. It goes to dr_mp3. `dr_wav.c` raises dr_wav's rate limit to 768 kHz.
- **The open picks one of the handle's own decoders by the file's first bytes, before any parser** (`openOwnDecoderInterleaved:`). A RIFF, RF64, Wave64, or FORM header goes to dr_wav. `fLaC`, after any ID3v2 tags, goes to dr_flac. An Ogg file goes to libvorbis. MPEG frames go to dr_mp3, after any ID3v2 tags or in a WAV's data chunk. In a file named as MPEG, the first frame may lie up to 64 KB past the tags, as CoreAudio allows. A file the decoder refuses goes to CoreAudio's parser. The check reads the file's first bytes, and the ten after each ID3v2 tag. The parser reads them anyway.
- **Apple's decoders play only what the handle's own cannot** (`VibeOwnDecoderCoding`, `AudioFileHandle.m`). When CoreAudio's parser opens a file for reading and names a container and coding one of the handle's decoders takes, that decoder has already refused the file. The read refuses it too, with `kAudioFileUnsupportedDataFormatError`. Apple's decoders get the codings the handle has no decoder for, such as AAC, ALAC, Opus, and GSM in a WAV, and the containers it does not parse, such as CAF and MP4. A metadata fallback still reads facts through the parser. A W64's facts come from there, though dr_wav plays it.
- **dr_flac and dr_wav state a file's facts as CoreAudio's parser does**: the format's flags, its packet and frame sizes, its width, and its channel layout. A PCM sample narrower than its bytes keeps its width, high-aligned: 20 bits in 3. dr_wav rounds an AIFF's up to whole bytes, so the open reads the COMM chunk's width itself. An AIFF's layout is its CHAN chunk (`VibeReadAIFFChunk` reads both). A WAV's is its channel mask. A FLAC's follows from its channel count. There are three known differences. The parser calls a sowt AIFF-C's 24 and 32-bit samples 16-bit. The handle states their true width. The parser also ignores an extensible WAV's valid bits and calls 24 bits in 32-bit containers 32-bit. The handle states 24, and a 24-bit device format then carries the file. The source-depth flag names 16, 20, 24, and 32 bits. The parser states no flag for a FLAC of any other depth. dr_flac states the narrowest flag that holds it. An 8 or 12-bit FLAC states 16, and a 28-bit FLAC states 32. With no flag, `audio/Player`'s bit-perfect output would assume 24 and report a 28-bit FLAC as Active. `testOwnDecodersStateWhatCoreAudioStates` compares every field and every surround layout's stereo fold on each fixture. Without the parser, a FLAC opens 3 to 14 times faster and a WAV or AIFF twice as fast (`open.*` in Vibe's VibeBenchComponents).
- **The MPEG open frames the stream itself** (`AudioFileHandle+MPEG.m`). It states CoreAudio's facts and length, except where CoreAudio is wrong. CoreAudio misses the Info frame of a mono or an MPEG-2 file, so it plays their encoder padding. It stops counting packets where a stream changes mode. It refuses free format. The walk takes the priming and remainder from the LAME tag, or from iTunes' iTunSMPB comment. It trusts a Xing, VBRI, or iTunes count only when the count fits the file. The stated bytes must cover the audio, apart from tags after it. Each counted frame must get a size the stream's frames can have. **TRAP: the stated bytes include the Xing, Info, or VBRI frame, and the count does not.** Counted against the frames, they failed every 320 kbps file at 44.1 kHz under 4.5 minutes, and its open walked every frame. The remainder is trimmed only when the stream holds exactly the packets stated. A frame that states no bit rate is free format. It runs to the next header of the stream, never past dr_mp3's largest free format frame, whether the whole stream is free format or damage left one frame so. The channels are the most any frame walked at open holds. A mono frame plays in both channels, and a stereo frame is mixed down. MPEG in another container, such as CAF, is Apple's. `testOwnDecodersStateWhatCoreAudioStates` compares every MPEG fixture.
- The vendored dr_ copies carry fixes of Vibe's own. Each one's doc in `third_party/` lists them. AAC decodes to float natively.
- **Ogg Vorbis is decoded by libvorbis on both platforms.** The handle's open gives every Ogg file to vorbisfile (`openVorbisInterleaved:`). vorbisfile finds the Vorbis stream among the streams the file starts, and skips a Skeleton or a video stream. A file with no Vorbis stream, such as Opus, goes to CoreAudio's parser. One vorbisfile refuses is refused. iOS's Ogg reader refuses Vorbis. macOS's decoder starts each file 128 frames late, and `testOggVorbis` fails once it no longer does. vorbisfile answers the facts: the rate, the channels in Vorbis I's order as labels, and the length from the last page's granule position. A chained file plays its leading streams that share the first's rate and channels, since a reader takes one format per file. macOS's parser plays only the first stream of such a chain. The handle counts the position itself, since vorbisfile's follows granule positions, which damage can set to anything.
- **TRAP: a Vorbis open reads the first audio page and the last 64 KB.** A file still downloading needs both. So the tail window `TailWindowMath.h` gives an Ogg file must hold 64 KB.
- Ogg Opus is CoreAudio's own reader and decoder, on both platforms.
- **Apple's Opus decoder ignores the header's output gain**, which RFC 7845 says a player must apply. The handle reads it from the `OpusHead` packet at open and scales Apple's decode by it (`VibeOpusOutputGain`). The samples are then bounded at +12 dBFS, as a damaged MP3 frame's are (`kVibeDecodeSampleBound`). `testOpusPlaysAtItsHeaderOutputGain` ends with a canary that fails once Apple applies the gain itself.
- **TRAP: FLAC in Ogg is refused at the parser open**, since that reader reports it no length and decodes only its first page. A metadata fallback opens the same way. `media/Metadata`'s TagLib parse refuses it as FLAC. Its row then fails to parse rather than look playable (`AudioFileHandle.m`, `testFLACInOggIsRefused`).
- **TRAP: a CAF's info chunk is checked before CoreAudio's info parser reads it**, since a forged entry count makes that parser loop forever. `infoDictionaryReadable` walks the chunk headers through the handle's own reads. It answers NO when the info chunk is absent, runs past the file, or declares more entries than its body could hold. A streamed CAF's data chunk of size -1 ends the walk, so an info chunk after it is dropped.

## Closing a file

**TRAP: a handle's last release never closes its file on the thread it lands on** (the dealloc). On a network share a close can wait on the server. The pieces let handles go where main waits: under `audio/Player`'s locks at a gapless promote and at a recycle, on its player queue when a parked file is dropped, on the file loader's state queue when an open is abandoned, and under `waveform/WaveformLoading`'s loader lock, which main's cancel takes, when a load ends. So a handle opened with an `interrupted` block hands its descriptor, or its parser opened by URL, to a serial close queue of its own. Its decoders and a callback parser still close in the dealloc, since they read through the handle. No call site needs to carry a release past a lock. A close stuck on a dead server holds the later ones. A handle opened with no block closes its files at its release. An app that moves files after reading them opens that way.

## Reading a file still downloading

**A file a remote transfer is still writing opens as a stream** (`CloudFileMaterializer availabilityForURL:`, `files/FileLoading/AGENTS.md`). The handle reads the part file at the final size. Every callback waits for the bytes it was asked for before its `pread`, never the rest of the block and never a read at or past the size. Or it copies them from the transfer's tail window when the wait says they are there and not on disk. A block fill takes one source, the window's bytes or the disk's. **TRAP:** the transfer can finish and rename its part over the URL between the lookup and the open, so a missing part waits for the transfer's verdict and opens the URL.

A wait ends ready, failed, or interrupted. A failed transfer is a read failure carrying the transfer's error, for good. **Interrupted is neither the end nor a failure.** `interruptReads` (any thread) or an open's `interrupted:` block ends a wait that would block. The read, seek, or open answers NO with an error `isInterruption:` names, and reads are refused until a seek after `allowReads`. **A lost read returns no bytes**, so every decoder sees one clean end of data. That seek restarts the two decoders that keep state across it:

- **TRAP:** dr_flac's seek skips a target it believes it is at and moves inside the frame it holds without reading, so it is restarted at its first frame.
- **TRAP:** ExtAudioFile serves packets the lost read fetched after a later seek, so it is rebuilt over the same parser.
- dr_wav's cursor never moved, and dr_mp3's seek rebuilds its decoder anyway, provided a lost read never shortens the packet count. vorbisfile's seek finds its page again from the bytes. A lost read reaches vorbisfile as a failed read, never as the stream's end (`VibeVorbisRead`).

**TRAP: an MP3 with no count that fits the file states no packet count.** A count comes from a Xing, Info, or VBRI frame, or from iTunes' comment. The walk counts one by reading every frame header to the end, so a stream of one would open only once downloaded. It opens uncounted instead, on a count from the frames of its head (`estimateMPEGPacketsAtRate:`, `AudioFileHandle+MPEG.m`). The open waits for 16 frames and walks on through those already on disk. If they share the first's bit rate, the count is what that rate gives the audio's bytes. Otherwise it is the count at their average size. **Either is an estimate** (`lengthIsEstimated`), since a headerless file can change rate after its intro. It is kept ahead of the cursor, so a reader never takes it for the end. It is settled from the walk's count when the reads reach the stream's end, or at the first read once the download is complete, on the reading thread. Seeks land exactly either way, since a packet is a fixed number of frames. A head that does not walk is still counted at open, waiting for its download.

- **TRAP:** the settle stores the length, then clears the flag with release ordering, and `lengthIsEstimated` reads it with acquire. A reader of both takes them as one pair (`lengthEstimated:`).
- How the player follows an estimate, and refuses nothing against one, is `audio/Player/AGENTS.md`. `audio/AudioTypes`' CUE window keeps a cue end past an estimate.

A whole file pays one lookup per open and one nil check per fill. The file loader's coordinator opens a readable transfer's file this way and interrupts the open when its run is cancelled. The open's deadline is the app's.

## Reading ahead on a network mount

**A file on a network mount reads ahead** (`files/FileLoading/Transfer/NetworkReadAhead`). The read-ahead itself is `files/FileLoading/AGENTS.md`'s: its thread, its blocks, its retries, and its orphans. The open decides before any I/O, and three things must hold:

- The opener passed an `interrupted` block, and it is not `VibeNeverWaitsForAStream`.
- No transfer's availability answers for the URL.
- The kernel's mount table says the file's mount is a network one (`VibeNetworkReadAheadApplies`).

The file loader's coordinator opens and `waveform/WaveformLoading`'s read ahead. A nil block, as an app's own one-off read may pass, and a metadata fallback read directly. **TRAP: both roads open the file nonblocking.** A FIFO with no writer then returns at once for `fstat` to refuse, and never parks an uncancellable open worker.

**A read the server fails never fails the open.** The read-ahead retries it until its handle is gone. Only the read-ahead's own `open` and `fstat` fail the open, with the direct road's errors. A persistent read error on bytes the open needs is retried, so that open fails at the app's open deadline. A dead server is then a wait, which `audio/Player` turns into a pause.

**Interrupted reads pause the fetch ahead.** `interruptReads` sets the availability's `readAheadPaused`, and the thread then fetches only a range a wait asks for. So a reader that skipped away stops pulling its file over the network. `allowReads` clears it and wakes the thread.

**The handle holds no descriptor.** Every read waits for its bytes in the availability, as a stream's does, and is copied out of the blocks. A wait that is Ready with nothing copied is the end of the file. The open waits for byte 0, then takes the noted size. The open's canceller wakes only a transfer, so the open's waits ask its `interrupted` block again every 0.25 s. Every later interrupt comes with a wake from `interruptReads`. `holdStream` has no transfer to hold. On a play's handle it raises the read-ahead's span to about 30 s of the file instead. That read-ahead then fetches ahead only while the plays' read-aheads sized before it are idle. The playing file's goes before the prefetch's (`files/FileLoading/AGENTS.md`). The QuickTime reader has no callback open, so its URL road finishes the availability first, which ends the thread. **An MP3 is counted exactly at open**, as a local file is. A headerless MP3 whose frames take longer than the open deadline to cross the wire fails to open. `waitingForBytes` rises while a read waits for a block.

**The handle's dealloc finishes the availability first**, with a "closed" error, and only then closes its decoders and parser. The thread exits once its current syscall returns. Until then it is an orphan (`files/FileLoading/AGENTS.md`). An open waits while eight are orphaned, and the app's open deadline still bounds that wait.

## The read-ahead's seam

**`AudioFileHandle+Debug.h` lets a test read a local file as if it were on a share.** `debugSetMountRule:` forces the mount rule per URL. `debugSetBeforeRead:` runs a hook on the read-ahead thread before each `pread`, outside every lock. The hook can throttle a read, stall it until released, fail it with an errno, or end the file there. Two counts are read back: the read-ahead threads alive, and those orphaned inside a read. `debugCloseQueue` is the queue a released handle's file closes on. The rule, the hook, and the counts are process-wide, so a test sets them for its own URLs and clears them in `tearDown`. The category forwards to `files/FileLoading`'s `NetworkReadAhead+Debug.h`, whose statics live in `NetworkReadAhead.m`. The seam compiles in every configuration and wraps its body in `#if DEBUG`.

## Tests

`Tests/audio/Decode/` holds the tests of the handle. `AudioFileHandleTests` covers the open's verdicts, the facts, the reads, the cursor, and the close queue. `AudioFileHandleStreamingTests` reads a file while its bytes arrive, and opens through the file loader's coordinator. `AudioFileHandleReadAheadTests` reads ahead on a forced network mount. Both share `AudioFileHandleStreamingTestCase`, which runs no tests. `AudioFileHandleOpenTests` checks that the coordinator delivers a real handle, through the opener `audio/Player` passes. `TailWindowMathTests` checks each format's window. **The streaming tests open a file with a chunk after its audio on the window `TailWindowMath.h` gives it**, so a window too small for such an open fails here. `files/RemoteFiles`' tests check that its store asks for that same window.

They write their own fixtures (`Tests/Support/AudioFileFixtures.h`). `VibeReadAheadScript` (`Tests/Support/`) scripts the read-ahead through the seam. It counts reads by file and offset, and can throttle them, stall them, fail them, or read nothing once. **The read-ahead counts are process-wide**, and a stalled thread outlives its handle as an orphan. A class that parks threads releases them in `tearDown` and waits for `threadsGone` before the next test counts. Vibe's tests compile both helpers from here.

**`AudioFileHandleFuzzTests` feeds seeded mutants of every fixture through the handle.** Each decoder family is a subclass: dr_wav's, dr_flac's, the MPEG decoders', and Apple's. It reads the fixtures an app generates when `VIBE_AUDIO_FIXTURES` names their folder, and the few sources it writes itself. Here nothing generates fixtures, so the dr_flac and MPEG families skip. Vibe's audio suite compiles the same file and runs it over Vibe's generated fixtures. `TEST_RUNNER_VIBE_FUZZ_ITERATIONS`, `TEST_RUNNER_VIBE_FUZZ_SEED`, and `TEST_RUNNER_VIBE_FUZZ_EXPORT` work as the file's header says.

The player's render suite reads files through the handle too. It is `audio/Player`'s, and an app's test target runs it over its generated fixtures. Vibe keeps the tests that need its own code: its corpus conformance test and its waveform loader's streaming tests.
