# audio/Player

Everything between a decoded file and the speaker: the transport, the voice bus, the master bus, the output unit, prefetch, gapless, crossfades, and the open's deadline. The `Mac/` half binds the output unit to a device and drives bit-perfect output. The `iOS/` half follows the route and recovers the output. It holds `AudioPlayer`, the engine, with its debug seam and its manual render pump. It came from Vibe. It depends on `core/Common`, `audio/AudioTypes` for the playable item and the CUE window math, `audio/DSP` for the fades, the varispeed, and the resampler, `audio/Decode` for the file handle, `audio/FX` for the DJ chain, `audio/Meter` for the live levels, `audio/OutputDevices` for the devices and the iOS session, and `files/FileLoading` for the open. Its sources are Objective-C. It reads no app's settings, strings, or types.

**What an app gives it.** Its item, any object adopting `VibePlayableItem` (`audio/AudioTypes`). The player only reads it and hands the same object back in every callback. Its delegate, `AudioPlayerDelegate`, told on main. Its settings, pushed through the player's properties and setters: the crossfade, Declick, the volume, the pitch, FX, and bit-perfect and exclusive output. On the mac, the modes each device keeps, through the delegate's `audioPlayer:outputModesForDeviceUID:bitPerfectOutput:exclusiveOutput:`. **And its error domain, pushed once at launch** (Error text, below). How Vibe hosts it is Vibe's `Audio/AGENTS.md`.

**`AudioPlayer.m` is the single writer of the state it publishes. Each category owns one vocabulary and declares its methods in its own header.** All of them share `AudioPlayerInternal.h`, which also declares `(PlatformOutput)` once for the two platform implementations. **That shared header is the cost of every split.** A category that pushes more state into it than it takes out of `AudioPlayer.m` is not worth making.

The reading path is `AudioPlayer.h` → `AudioPlayer.m` → `AudioVoiceBus.h` → `AudioPlayer+Pipeline.h` → `AudioMasterBus.h` → the platform half.

## The model in one page

The player owns playback and renders it. There is no `AVAudioEngine`. One C function, `VibeMasterBusRender` (`AudioMasterBus`), renders `voice bus → [varispeed] → [FX] → [meter] → [volume]` straight into the output's buffers, on both platforms.

- The **voice bus** (`AudioVoiceBus`) is decode → ring → per-frame gain → mix.
- The **varispeed** is `audio/DSP`'s converter. The **FX** units are Apple's DSP, hosted through the AudioUnit C API (`audio/FX`). Both are skipped while they have nothing to do.
- The **meter** is `audio/Meter`'s analyzer, which an app's level indicators read.
- The **volume** is `AudioPlayer.volume`'s gain. It is skipped at exactly 1, so full volume leaves every sample untouched (`testVolumeIsExactAtFullAndSilentAtZero`). It ramps across one slice when it moves under a running output. It lands on its target directly at every output start, so a start plays at the volume it was left at. The debug silent output is its target of 0. **TRAP: a zero-filled volume is silence**, so `VibeMasterBusCreate` starts it at full volume.

One **output unit** pulls the render on both platforms: `AudioOutputUnit`, an output audio unit the player hosts, calling the render through a C proc. On macOS it is HALOutput bound to the chosen device (Mac/, below). On iOS it is RemoteIO, whose route is `AVAudioSession`'s (iOS/, below).

- A **voice** is one file being rendered: a decoder filling a ring, a gain with at most one pending ramp, and an optional queued successor file. At most one voice is **current**, the transport's track. The rest are **retiring**, fading out after a track change, seek or stop, and dying on their own.
- The **transport** (`AudioPlayer.m`) is the state machine `{Stopped, Loading, Playing, Paused}`. State changes run on the player queue. Delegate events are dispatched to main. Nothing in the transport waits for a fade.
- The transport hears three things from the bus, through a **drain** it runs itself: a voice went **live** (its first frames are buffered); the current voice passed its **boundary** into the queued successor (promote, `didAutoAdvance`); a voice **ended**. A current voice's end is `didFinishPlaying` on clean EOF or an attributed error on failure. A retiring voice's end feeds the output-liveness fold.
- **Every fade exists only to keep the output click-free.** A ramp is evaluated per frame on the audio thread from the frame index, so it lands on its target exactly. **Declick** (`AudioPlayer.declick`, default on) decides what a transport edge does: on, the ≤10 ms declick and every other frame untouched; off, a cut. A crossfade longer than the declick is the app's choice and fades either way. Bit-perfect output holds the crossfade at the declick, so with Declick off it applies no gain at all.

**Loading keeps its intent live, and buffering is a flag beside the state, never a state** (Opening a file, below). Loading covers the in-flight open and reports zero position and duration. Play/pause during it toggles whether the opened file starts or parks, and a seek replaces its start position. Exactly one of `isPlaying`/`isPaused`/`isStopped` is true, and `isLoading` is orthogonal. A pause reports Paused the moment it is requested. An action that must order itself after already-submitted transport commands calls `getPlaybackIntent:forTrack:` once. Loading answers the request's intent, otherwise `(position, state == Paused)`.

**`PlaybackRequestCoordinator` owns the in-flight open** (Foundation-only, tested). An identifier is never reused, not even across `invalidate`, so a worker blocked on a dead mount cannot consume a later open of the same path. A re-drop or replay rebinds the row in place instead of starting a second open, re-firing `didBeginLoading:` when the request is already slow. A seek is accepted on either the row or the exact submitted play. The identifier covers a seek issued before its play reached the queue, and the row one issued after.

**The published tuple is written whole.** `publishState:voice:file:window:startSeconds:baseFrames:` writes state, voice, file (as its rate and the track's window, so a getter never messages an object) and the position's origin under `_stateLock` in one acquisition. The two `unpublishVoiceOnQueue…` variants and `republishEstimatedWindowOnQueue` write part of it and never move the origin. The terminal variant, at a track's natural end, drops the file with the voice, so a stream's last reader can go. The stall's park (`publishPausedWithoutVoiceOnQueueAtSeconds:`) moves the origin with the state, voice and file in one acquisition, and keeps the window. Position is `startSeconds + (consumed − promotedBaseFrames) / busRate`, read from the voice's own counter, so it holds across an output stop and needs no cache.

## The voice bus

`AudioVoiceBus.h` carries the contract. This is the shape.

| File | Owns |
| --- | --- |
| `AudioVoiceBus.h` | the contract: voices, ramps, events, the snapshot, and `VibeVoiceBusRender`'s signature |
| `AudioVoiceBusInternal.h` | the private header: the slot and mix structs, the record, every ivar, the `(Decoder)` methods the queue side calls, and the `(Testing)` seam |
| `AudioVoiceBus.m` | the queue side: identity, starts and binds, ramps, stopped and withheld reads, the successor hand-off, kills, snapshots, the drain and inline decoding |
| `AudioVoiceBusRender.m` | the audio thread: `VibeVoiceBusRender` and its mix helpers, in plain C |
| `AudioVoiceBus+Decoder.m` | the decode pool's side: the prepare and its conversion, failures, the recycle, the fills, the converter feed, the chunk decode, the stream's end and its reopen |

**Format.** The bus has one format for its life, the output's: float32 non-interleaved stereo at the output's rate. So a mode toggle or a device rate change rebuilds the segment, and the bus owns conversion. A file is read direct when its rate, sample format and channels are the bus's (`VibePCMFormatsMatch`, the one rule the bus, the pipeline and the bit-perfect splice share). Under bit-perfect output the prepare has moved the device and the output to the file's rate first, so a stereo file at that rate is the bitstream unchanged.

Otherwise it is converted on the decode queue by a `VibeResampler` (`audio/DSP`'s `AudioResampler.h`), which also serves a device that refuses a file's rate. That is **r8brain-free-src on both platforms**: linear phase, its 24-bit preset, a 1% transition band, with no quality setting (Vibe's `docs/audio-quality.md`; `ResamplerQualityTests` holds it to its bounds). It pulls float32 through a `VibeResamplerInputProc`. A file that runs dry with the stream open answers no frames, which ends that fill and keeps the filter primed for a successor. r8brain has no end-of-stream call, so the stream's end is the silence flush below.

A channel difference is mixed first, at the file's own rate, through AudioToolbox's standard matrix (`kAudioFormatProperty_MatrixMixMap`). A 5.1 file's center and surrounds fold into stereo at −3 dB and its LFE is dropped. Mono goes into every channel, and a file with no standard layout keeps its first channels. So a converter carries only the bus's channels. Every file reaches the bus as the float32 its reader decodes. A lossy one's precision is left to the output's one rounding into the device.

**The decoders are the file handle's** (`audio/Decode/AGENTS.md`). Which decoder takes a file, the facts each states, and each one's traps are in that doc. `audioPathSnapshot` reports the source segment and the conversions in force, the decoder included.

**Slots.** Eight, each a plain C struct with a power-of-two ring of at least one second at the bus rate. A slot is allocated once and freed only after the bus's pointer was withdrawn from the master bus and no render is inside it (`afterRenderLeavesOnQueue:`). A render not seen outside within the wait's bound keeps the bus alive until it is. State runs `free → armed → live → dead → free`:

- The queue does free→armed and armed→dead. The decoder does armed→live, and armed→dead on failure before the first frame. **Only the audio thread does live→dead** (end of stream, or a retire landing; a kill is a retire of zero frames). An armed slot was never rendered, so its death needs no render to retire.
- dead→free runs on the slot's own decode queue after a render has completed past the death. **TRAP: on any other queue it disposes the converter under a turn still in flight.** It cleans only the death it was queued for and clears the slot's generation. Every decode turn checks that generation first, so a turn queued for the dead voice cannot enter the slot while the next voice binds it.
- Counters are never reset. `written` and `consumed` are monotonic for the slot's life, and the recycle aligns them. A bind records the two origins a snapshot subtracts as atomics, with the generation as the seqlock's version. So a snapshot polled across a slot's reuse retries instead of mixing two voices.
- A start always receives an identity. At two free slots the oldest retiring voice is cut. A start that still finds no slot is **pending**, bound when the drain frees one, however long that takes. A free slot guarantees a queue for its own file, and a successor never holds up binding.
- **Every started voice ends exactly once through the drain**, a pending one killed before it had a slot included.

**The audio thread** runs `VibeVoiceBusRender`, a C function under `CA_REALTIME_API` and `-Werror=function-effects`: a lock, allocation, Objective-C send or dispatch call is a build error. It reads plain memory and atomics, writes the buffers, stamps from the block's timestamp, and never signals anyone. Per live voice it adopts a new ramp sequence from the current gain (adoption un-pauses). It mixes `min(frames, written − consumed)` at the per-frame gain, in at most two contiguous spans, one vDSP operation per channel each. It zero-fills the rest as an underrun unless the end is known, and lands a pause or retire on its exact frame. `renderSequence` and `inRender` let the queue tell "no render is inside any slot" from "the output says it is stopped".

**Gain.** One 64-bit atomic per voice: target, frames, curve, action (none, pause, retire) and sequence. The declick curve is **linear**, since a 10 ms log ramp's last-sample slope fails the envelope bound at 44.1 kHz. Every longer fade is one side of an equal-power crossfade (`audio/DSP`'s `FadeMath.h`, tested per frame there). **`rampOnQueueToGain:` is the one gain rule.** Under bit-perfect output every ramp is clamped to the declick length, since a play submitted before the mode landed carries the length it was retired with. With Declick off every declick-length ramp is zero frames, a cut, in either mode, while a longer one is the app's crossfade. `bitPerfectOnQueue` is the mode itself, which the segment choice reads. Nothing renders under a stopped output, so retiring voices are killed there, and a pause is a cut that lands at the first render after any restart.

**The decode pool** is eight serial queues per bus (`QOS_CLASS_USER_INTERACTIVE`), or the caller's thread under the frame-driven pump. An unrelated file takes an unused queue, so a stalled old read cannot hold its start. Overlapping reads of one handle, a queued successor's included, stay on one queue (`decodeQueueReadingFile:`). Queue ownership follows every occupied slot using it, since a seek can still use that reader after the old slot is freed. Only the assigned queue touches an `AudioFileHandle` after a start.

- **TRAP: a voice has left its file only once its reads are stopped for good and its last turn is over** (`fillScheduled` clear). On `readsAllowed` alone a second queue takes the cursor with the old read still inside, and a withheld voice reads again. A voice may still occupy its slot, fading what it buffered.
- A successor whose file another queue still reads waits in the record's `waitingSuccessor`. The drain hands it to the decoder once that queue has left the file (`publishWaitingSuccessorForSlot:`). A voice that ends first ends as an ordinary track end.
- The decoder asks for a drain (`needsDrain`) when a voice goes live or fails before its first frame, when a stopped voice's last turn ends, and when a slot frees. So these happen under a stopped output too, which has no drain timer.
- Turns are 4096 frames: live at one, filled to the ring, topped up below half.
- **Clean EOF follows a successful read**: a short or empty read, or reaching the declared end. A read error never becomes EOF. A refused seek or read ends with `VibeVoiceEndFailed`. The record keeps the error, the failing URL and the exact handle until the drain consumes it. A failed read's valid prefix is published once. A converter that cannot be made fails the prepare, and a made one cannot fail. A refused successor seek flushes the shared converter's predecessor tail before ending. An unheard successor cannot fail the predecessor's row. Retired and superseded voices cannot fail a newer submission.
- **The stream's end is declared** (the converter's tail pushed out and `endOfStream` published) only once the render is within two chunks of the file's last frame, or a successor needs a converter of its own. Until then a converter stays open past its file, primed for a successor named late. **TRAP: the tail is pushed out with silence and cut at the frames fed, at the bus rate (`streamEndForRecord:written:`).** r8brain is never told the end, and a fill that stops at zero frames leaves its filter's length of the file inside it. A bus-format file has nothing to keep open and ends at once.

**A stopped voice's waiting read is woken.** The call that stops a voice's reads for good (`stopReadsOfSlot:`, behind `stopReadingForVoice:`, `stopReadingThen:`, a kill, and the drain that reports a death) interrupts its file and successor (`AudioFileHandle interruptReads`). A turn parked at a streaming file's edge then returns at once instead of holding the queue and the file. The transport also stops a dead voice's reads when it retires one. A voice retired at declick length reads no more, so its file may be handed to the next voice at once. An interrupted read or seek of a stopped voice ends its turn and writes nothing. One whose reads are still allowed fails as any read error does.

- **TRAP: only the call that clears `readsAllowed` interrupts**, since a voice already stopped may have handed its file on.
- **TRAP: reads are allowed again only at a voice's positioning seek** (`decodeChunkForSlot:`, its first and each successor's), on its own decode queue. The voice before it was stopped and interrupted on the player queue before this one started. A turn of it still in flight put this voice on its serial queue. So no other read is inside the file. A stop between the allow and the seek is caught by the re-check after it.

Every interrupt is issued on the player queue before any newer voice on the file can start, so that ordering follows from where the calls sit, not from timing. The frame-driven pump's inline fill would block on a waiting read, so the render suite plays streams on the decode pool.

**The successor.** `queueSuccessor:` hands the parked file to the current voice. The decoder continues into it at the file's end and publishes the **boundary** before the successor's first frames, so a render that sees them sees where they begin. The boundary is computed from the frames the converter was fed, at the bus rate, never read off `written`. The resampler holds its filter's length of the first file back until the successor pushes it out, so a boundary read off `written` promotes the next track early. A successor in the same format and decode format continues through the same converter, which is told nothing of the boundary, so the filter carries across it. Any other successor gets a converter of its own after the first one's tail.

- The hand-off is one atomic `{none, queued, switching, taking back, taken back}`. The decoder wins queued→switching and an unqueue wins queued→none. **The decoder's claim commits the voice from the moment it is made**, before the boundary is published. So an unqueue against it reports the switch.
- **A switch the render has not reached is taken back** (`takeBackSuccessorForVoice:`). The decoder runs at least half a ring ahead, so near a file's end it is already reading the successor. The queue raises the slot's **cut** at the boundary. A render that sees the cut mixes nothing past it. **TRAP:** only the render knows whether it passed the boundary. So the take-back waits out the render in flight, bounded as the reopen's wait is, and `consumed` is the verdict. At or before the boundary, the boundary is withdrawn, and the decoder's queue drops the frames past the cut: `written` and the end move back to it, then the cut lifts. The voice ends there as one whose successor was never named, and a successor queued since reopens the stream at that frame. Past the boundary the cut lifts, and the successor is already sounding: the splice stands, as if the change had come after the drain, and the promote queues the new park behind it. Under a stuck render the cut lifts and the transport re-voices. So does a successor whose resampler still holds the first file's last frames, since there is no cut before them.
- **A stream whose end was declared before its successor was named is reopened**, with a converter of its own. **TRAP:** only the audio thread decides the voice reached its end. The decoder withdraws the end, waits out every render that could have loaded it, and reads the verdict. A voice that reached the end died there and ends as it would have. Otherwise the boundary is published at the old end and the stream goes on. **TRAP:** that wait is bounded (100 ms) and yields to stopped reads. With no verdict the end goes back and the voice ends there. A stuck render must never hold the decode queue.
- **One voice chains any number of successors.** The drain reports boundaries by value, and the transport queues the next only after the previous one was reported.

**The drain** (`drainVoiceBusOnQueue`) binds pending voices, emits each voice's events in the order live → boundary → ended, tops up rings, and recycles dead slots. It tops up no voice that can write nothing: reads stopped, end published with no successor, or a stream held open past its file while the render is far from it. On hardware it is a timer on the player queue **only while the output is running and a slot is occupied**, plus a hop from the decoder. Under the pump it runs after every rendered slice. The timer is 10 ms while anything is due (a fade, deferred render-leave work, or the bus's `promptDrainDue`) and 100 ms otherwise. **What the bus has due is found by the drain's own pass**, slot by slot. A start or a kill raises it at once on the player queue. A boundary or end the decoder publishes at its file's end is at least half a ring ahead of the render, so the steady drain is in time. **A converted stream's end is not.** Held open for a late successor, it is declared only within `kOpenStreamReserveFrames` of the render (85 ms at 96 kHz). So the hold is prompt while it is current (`heldOpenAt` still matching `written`). A successor that continues the stream writes past it, and the cadence returns to steady. A path that makes something due without a drain re-evaluates the timer itself.

## Threading

**Every pipeline mutation runs on the serial player queue. The getters take the `os_unfair_lock` snapshot and compute off it**, never a queue round trip. The output unit's HAL calls (bind on macOS, configure, start, stop) each wait on the hardware's IO thread. They run on the unit's own serial queue in the order the player queue issued them, so no device holds the player queue. What the player queue still reads of a macOS device is bounded, with stated exceptions (Mac/, below). On iOS it reads the session's rate before every start and its latencies for the reports. The queue's QoS is Default, as is the unit's queue it waits on in `waitUntilIdle`. The latency-critical work, the open and the decode, runs on its own lanes. The render suite checks the conversion through the production renderer against an off-bus reference, and reads the algorithm back through `debugCurrentConversion`.

**TRAP: `os_unfair_lock` is not recursive.** The public `pitch` getter takes `_stateLock`, so code that holds the lock reads `_pitch` directly. Taking the lock again aborts.

**TRAP: a handle's last release never closes its file on the thread it lands on** (`audio/Decode/AGENTS.md`, Closing a file). On a network share a close can wait on the server. Handles are let go where main waits: under `_stateLock` at a gapless promote, under `_tableLock` at a recycle, on the player queue when the park is dropped, and on the coordinator's state queue when an open is abandoned. A handle opened with an `interrupted` block closes its file on a serial queue of its own, so no call site needs to carry a release past a lock.

**TRAP: every buffer the render is the first to write is written once where it is allocated.** A `calloc`'d page is mapped at its first write, and a fault on the audio thread waits for a free page. Use `vDSP_vclr`, not `memset`: clang drops a `memset(0)` after `calloc` (each allocation carries the `TRAP:`).

**Nothing the render could be inside is freed or reset on a timeout.** A withdrawal publishes the pointer's removal and waits, bounded, for the render to be seen outside. When the bound runs out, the teardown is parked and run at the first later wait or drain that sees the render outside (`afterRenderLeavesOnQueue:`). The player's dealloc leaks the pipeline rather than free under a render. Each hosting is one allocation the render reads through one pointer: the varispeed's stage, and the FX chain's units and scratch. A re-host swaps the pointer, and the old hosting waits for a late render the same way, as does a varispeed kernel the pitch replaced.

**The master bus lives from the player's init to its dealloc.** TRAP: it is allocated in the synchronous init, never in the async init block. Queue work can run before that block, and every queue-side reader and the dealloc dereference it unchecked.

**The pipeline admits one render at a time.** The master bus's `inRender` is a door the render takes at entry and releases at exit. An output unit's callback that finds another render inside renders silence and touches nothing. That is a stuck render outliving its unit's bounded stop while the next unit began. `renderRefusals` (`debugRenderCounts`) counts it. **TRAP: only the render that took the door releases it.** A flag any render could clear lets the new unit's first callback clear the stuck render's, and the drain then frees the bus that render is still mixing.

**A voice's identity rejects stale voice work.** A `VibeVoiceID` is minted once per start and is the slot's generation while it holds one. A stale id never addresses a reused slot. A ramp or event for a voice the transport no longer publishes is simply not the current voice. Deliveries to main are guarded by submitted-play identity (below).

## Crossfades, pauses and seeks

**`VibeIncomingFadeMilliseconds` (`AudioPrefetchRules.h`, tested) is the one place that decides a play's fade length.** `crossfadeMilliseconds` defaults to the 10 ms declick minimum, which an app may show as off. The player sets no upper bound, so an app chooses its own. It applies only when a play replaces an audibly playing track. First plays, the pause/seek/stop declicks and `play:atPosition:startPaused:` force the minimum. A track change is a true crossfade on one bus: the outgoing voice fades on its own ramp while the incoming one fades in beside it, and nothing is rewired.

**A track end crossfades from inside the player**, since an app's `play:` after it would find nothing audible. Each drain asks `maybeCrossfadeIntoParkOnQueue`. `VibeTrackEndCrossfadeMilliseconds` (tested) says when it is due: the setting held to half of each track and to what remains, one steady drain early. The park then starts as its own voice fading in while the current one fades out. `adoptTrack:…`, which the gapless promote ends in too, makes it current and tells the app through `didAutoAdvanceFromTrack:toTrack:`. Nothing parked (the queue's end, a pause at track end), an estimated window, buffering and bit-perfect output each leave the ordinary track end.

**With Declick off every declick-length edge cuts**, in either mode. `testBitPerfectTransportCutsWithoutChangingSamples` and `testDeclickOffCutsOrdinaryEdgesAndKeepsTheCrossfade` require every audible frame across seek, pause, resume, a track change and stop to continue an exact excerpt of the source. The second keeps a 2 s crossfade fading. With Declick on, each edge is the 10 ms declick and nothing else is touched (`testBitPerfectDeclickRampsOnlyTheEdges`). The choice is `AudioPlayer.declick`, which an app pushes.

**A voice that cannot be heard is killed, not faded**: not yet live, paused, cut with Declick off, or under a stopped output. So only fading voices are `_retiringVoices` (`retiredFades` in `debugRenderCounts`). Stop, pause, a parked play and the failure reset cut every retiring voice to the declick length. Skips never do, so rapid skips keep the full fade-out.

**A seek names its track, or takes the player's.** `seekToPosition:` aims at the play the player holds when it is called, or the one submitted or loading. The queue drops it if that play is no longer current. A gapless splice moves the current track on the player's queue before `didAutoAdvanceFromTrack:toTrack:` reaches main, so an app that moves its own queue only at that callback can still show the outgoing track. `seekToPosition:ofTrack:` takes the app's track instead, and the queue's check drops the seek once the splice has happened, whichever side of the call it fell on (`testASeekNamingTheOutgoingTrackAfterASpliceIsDropped`).

**A seek is a new voice at the target with the old one fading out beside it.** It is one shape for playing and paused, with nothing rescheduled. `didFinishSeeking:` settles every submitted seek intent, dropped ones included. It does not certify a decoder position. A refused decoder seek takes the current play's identity-guarded error path. **TRAP: the old voice retires before the new one starts** (`revoiceOnQueueAtPosition`). Both read the same `AudioFileHandle`. While a turn of the old voice is in flight, the new voice takes its decode queue, so its first turn positions the cursor after that read returned. A declick-length retire stops the old voice's further reads (`testSeekStopsTheOldVoiceReadingBeforeItsFileIsHandedOn`).

**A pause fades the voice to silence and stops consuming on the exact landing frame.** A resume is a newer ramp, which un-pauses by being newer.

**The deferred idle stop** (Stopped or Paused for 6 s) releases the output device. It is cancelled by generation in `startOutputOnQueue:`, the one funnel every start and resume goes through. It waits past the 6 s while an FX send's tail still rings, re-checking each second for at most the chain's longest declared tail (`AudioFX.sendsActive`, `longestTailSeconds`). A reverb released before a pause rings out, and a send held through the pause cannot hold the device.

**TRAP: only the manual pump may start without an output unit.** Otherwise Playing and `didStartPlaying:` publish with no callback to advance the voice, and the app gets neither audio nor an error. A missing output unit fails the start with `VibeAudioErrorEngineStartFailed`. A start the unit refuses later, after Playing was published, parks the voice Paused and reports the same error on either platform (`outputUnitFailedOnQueue:`). A refused macOS bind reports `VibeAudioErrorDeviceUnavailable`. Voices keep their state across an output stop. A paused idle stop, a rebind that keeps the output's format and an iOS system stop reschedule nothing. A format change rebuilds the segment and re-voices.

**The source segment is built lazily** at the first settlement, and rebuilt only when the mode or the output's format differs. A rebuild kills every voice, so its callers guarantee nothing audible and re-voice at the retained intent (Mac/, below). **TRAP: the re-voice takes the same `AudioFileHandle`, and the old bus's decoder may be inside a read of it**, since its queued turns retain the bus. So the rebuild stops the old bus's reading and is told once every one of its decode queues has left its turn (`stopReadingThen:`). Until then it withholds every file the old bus may be inside from the new bus's voices (`filesInUse`, `withholdReadsOfFile:` / `allowReadsOfFile:`, counted per retired bus in `_retiredDecoderFiles`). One report covers all eight queues, so a read stalled on any of them withholds every file the old bus held. `filesInUse` is read under the table lock the decoder writes a record's file pair under, so a handoff in flight lists the successor in one field or the other. A voice started on a withheld file reads nothing until then. A successor queued on one is refused and asked for again. **The player queue never joins the decoder**, since a read on a stalled mount would hold every transport command behind it.

## The FX segment and the pitch stage

**`AudioPlayer` owns one `AudioFX` (readonly `fx`) from its synchronous init, on both platforms**, so an app's controls and the tempo feed stay stable. The chain is `audio/FX`. Its topology, its render, its intent, and its traps are `audio/FX/AGENTS.md`'s. The player hands it the player queue, `scheduleAfterSeconds:block:`, and `afterRenderLeavesOnQueue:`. So the chain's ramps ride the pump's clock under manual rendering.

**The player publishes the chain's pointer into the master bus after a connect, and withdraws it before a disconnect or a re-host** (`reconcileFXOnQueue`). The pipeline runs at the device's rate on the mac, so a device switch across rates hosts the units again. An iOS media-services reset withdraws the chain and calls `markDead`. Hosting the ten units runs on the player queue at the first enabled connect. That happens during launch if FX starts enabled. A play submitted during hosting waits behind it.

**Enabling and bypass.** On the mac, `setBitPerfectOutput:exclusiveOutput:enableFX:allowAnyDevice:` applies both settings through the playback-preserving device rebuild. Bit-perfect outranks the stored FX preference, and leaving it restores that preference. iOS applies the setting through `setFXEnabled:`, which stops the output, reconciles, and puts a playing track back (`resumeOutputAfterEditOnQueue:reason:`). The setters clear effect intent synchronously, on the caller's thread, when they submit a bypass (`clearFXIntent`). The queued bypass only preempts ramps and resets processing and tails, so it cannot erase a later control's action. `connected` answers whether the segment is in the chain.

**`AudioVarispeed` is the pitch stage, and it is not part of the FX segment.** It is `audio/DSP`'s. Its kernel, its edges, its zero-pitch bypass and its standalone tests are documented there. **The player hosts one per source segment**, before the FX segment, at the bus rate, and only on macOS (`ensureSourceSegmentOnQueueRebuilt:`). Bit-perfect output and iOS have no varispeed. Pitch is the ratio, 1 + pitch / 100. The render hands the stage each slice, and the stage pulls the bus through `VibeMasterBusSource` at the slice's stamp. `applyPitchOnQueue:` sets the stage's pitch and frees the table it replaced through `afterRenderLeavesOnQueue:`. At zero pitch the render skips it, so the track is the file exactly (`testZeroPitchIsBitPerfectAndTogglesAreClickFree`). At zero pitch settled the ring is not written (`varispeedHistoryWrites` in `debugRenderCounts` holds flat).

The player-level tests of the stage render it through the player. `testPitchEngagesAndDisengagesAtTheExactFrame` checks the engage and return at every rate from 44.1 to 192 kHz and in mono. `testARampDownKeepsTheWiderKernel` checks the kernel kept across a ramp down. `testPitchedTransportKeepsThePositionHeard` reads a sawtooth through a seek, a pause past the idle stop, a gapless splice and an output rate change. `testALongPitchedPlayKeepsItsPosition` reads every frame of a 6.5-minute play, past 2^24 frames, and its track end. `testPitchQuality` holds the stage to −145 dB of distortion and false tones, flat to 20 kHz, at 48 and 96 kHz.

## Prefetch and gapless

**An app's `prefetchTrack:` (or `requestPrefetchTrack:`) on every track start pre-opens what follows the track at its end.** What follows is the app's to decide. The next `play:` of that source consumes the parked `AudioFileHandle`. The request state is `AudioPrefetchRules.h`. A prefetch of another source (`sourceKey`, so another window of the file being opened too) requested during an open is retained and suppressed. That open's success resumes it. Its failure, abandonment, a newer play (same-path rebind included) or a later prefetch drops it. Its identity also drops every late callback. There is no handshake with the loading side, because the foreground rule is derived inside the coordinator (`files/FileLoading/AGENTS.md`).

**At play submission an unrelated prefetch is cancelled before the foreground open starts**, so its transfer cannot compete with the file the user chose. A prefetch of the track being played stays alive. Its handle run and the playback run ride one path claim, and whichever succeeds first consumes the play request. The winner retires the loser's park state, so a play never leaves its own track parked. A repeat of one track parks it again on purpose, by the prefetch after its start.

**The successor is the park itself.** `maybeArmSuccessorOnQueue` queues the parked file on the current voice when the crossfade is at its minimum or the successor continues the recording (`VibeGaplessArmAllowed`). Under bit-perfect output the next file must also want the device's current rate and channels, since one voice cannot switch the device. No second handle exists. The boundary event promotes the successor in place, with no stop and no fade. The bus frames consumed before it become the new base for the position. It fires `didAutoAdvanceFromTrack:toTrack:`, so the app advances its queue without `play:`. It **consumes the park**, so a replay of the promoted item opens fresh.

- **A repeat of one track parks the playing track's own object**: a second handle on the same file, spliced into its own start like any successor (`testATrackSplicesIntoItselfGaplessly`; `testACueRowSplicesIntoItsOwnWindow`).
- **A track's end fires exactly one of `didFinishPlaying:` or the auto-advance callback, never both.**
- When the app's successor changes under a queued one, or the crossfade setting is raised, `unqueueSuccessorOnQueue` drops it. The voice then ends at its own file. If the decoder had already switched into it and the render has not reached the boundary, the bus takes it back, so the file's last frame is followed by nothing or by the next park, with no gap (`AudioPlayerReparkTests`). Once the render has passed the boundary, reported or not, the successor plays on and is promoted, and the new park follows it. Otherwise the current file is re-voiced at its position, so the buffered successor dies with the old voice. Lowering the setting re-queues the park.

The MPEG open honors LAME and iTunes gapless metadata. CoreAudio honors iTunes' for AAC. So tagged MP3 and AAC files continue seamlessly, as all lossless files do. An untagged MP3's encoder padding is the one gap this cannot remove. `isGaplessArmed` surfaces the queued state.

**A main-thread action snapshots its track at dispatch**, because a promote can land between the action and its queue block. `seekToPosition:` and `finishCurrentTrack` drop the request if the boundary advanced it.

## Cue rows play a window

**The player takes `id<VibePlayableItem>` and hands back the object it was given.** The protocol is the item's file, its window in CD frames, `sourceKey` and `cacheKey`. The player only reads it. Nothing in it is about tags, names or art. Every delegate callback carries the submitted object, so a receiver can compare by identity.

**A cue row is a window of its file, and the player plays it as if it were the whole file.** So every track-end path (gapless promote, `didFinishPlaying:`, a pause at track end) applies at the window's end unchanged. `VibeCueWindow` (`audio/AudioTypes`' `CueWindowMath.h`, tested there) turns the item's CD-frame window into file frames at the file's rate, at settlement, at arm and at promote. Two rows meeting at a marker round to the same point, so they stay contiguous at a rate 75 does not divide. The tuple publishes the window as the length, so `duration` is the window and `position` starts at its start. `VibeClampedStartFrame` clamps every start and seek inside it.

The bus takes an end frame per voice and per successor: the row's cue end in file frames, unclamped, or 0 for a window running to the file's end (`VibeCueEndFrame`). It is never derived from the length. So a whole file ends where its stream really ends, not at a lossy or streaming length's estimate. The bus stops reading at the end frame, counting from its own cursor, never from `framePosition`. That answers 0 when `ExtAudioFileTell` fails, and an end clamped against it reads into the next row.

**Opens and handles are per file; what sounds is per window.** The open's rebind stays keyed by the file's path, so a pick of another row of a file being opened rebinds that open, and settlement reads the new row's window. The park, the prefetch and the successor compare `sourceKey` (the path plus the window). So the next row of a file is a park of its own, and one prefetched while its file is still opening waits behind that open. **The next window of the same file continues gaplessly whatever the crossfade** (`VibePlayableItemIsFollowedContiguouslyBy`, `VibeGaplessArmAllowed`'s second input). Otherwise one recording would crossfade with itself, or gap at every marker. **TRAP: that is the one successor a long crossfade can have, so an explicit play of it must not take the park** (`playOnQueue`). The voice retiring over the crossfade keeps reading, and may be inside that very handle. The play opens its own.

## Settlement identity

**A settlement for a superseded submission is never delivered, and it is matched by submitted-play identity, never by track.** `didStartPlaying:` and the play-path errors are dropped on main by `submittedPlayIsCurrent:`. It is checked inside the delivery block, because what matters is whether a newer play existed when the callback ran. The comparison is `PlaybackDeliveryRules.h` (tested): `VibePlaybackDeliveryIsCurrent`, and `VibePlaybackSubmissionStateIsUnchanged` for the media-services reset, where zero is a valid initial snapshot. The coordinator's own rule cannot cover this: once a result is dispatched to main, nothing can retract it. Replaying the same item hands the player the same object and URL, so a content-based guard would accept the previous play's settlement.

**Resume and seek-restart failures use the same identity, though their errors carry no URL.** They belong to the sounding voice, whose `_activeSubmittedPlayIdentifier` survives gapless promotion. A same-row replay could otherwise make the app accept the old error and tear down the newer play's state.

**Every callback about a play names it by request identifier** (`AudioPlayer.h`, Request identifiers). The request identifier is the submission identity made public. `requestPlay:` returns it. Plays and prefetches draw from one sequence, `_lastRequestIdentifier`, under `_stateLock`, so no two requests share one. `_currentRequestIdentifier` names `currentTrack`'s play and is written with it. An advance moves it to the identifier `requestPrefetchTrack:` returned, carried through the park and the successor. `_activeSubmittedPlayIdentifier` stays the original play's, since delivery is still matched against the newest play. A stalled play's replay is a new submission that keeps the stalled play's identifier (`requestIdentifierForSubmittedPlay:`), so the app sees one play throughout. The four transport callbacks that carry it have an identifier form beside the plain one. The player sends the identifier form when the delegate has it, and the plain one otherwise, so a delegate written before them keeps working.

**TRAP: the counter is `_nextSubmittedPlayIdentifier`, which only increments, never `_lastSubmittedPlayIdentifier`.** That one is the pre-Loading handoff, cleared to 0 once its play reaches Loading. Compared against it, every settlement reads as superseded, nothing is delivered, and whatever an app releases on settlement is stranded.

**The header holds only what the player decides.** When Previous is available, when an empty seek's settlement is current, and when a deferred metadata sweep runs are each app's own. Vibe keeps them beside its shells.

## Opening a file

**Files open off-queue against an abandon deadline, so a cloud placeholder cannot wedge playback.** A slow open surfaces Loading instead. `files/FileLoading`'s `AudioFileOpenTimeoutMath.h` owns the monotonic deadline: a 60 s no-progress baseline, extended (never shortened) to 60 s past each positive raw movement. `AudioLoadingConfiguration.openTimeouts` is snapshotted when the open starts, so a configuration change cannot move its deadline. The claim, admission and transfer machinery underneath is `files/FileLoading/AGENTS.md`'s. The play and the prefetch pass the coordinator `VibePlayerFileOpener`, which opens planar float32 with the run's `interrupted` block. The coordinator names no handle class (`ServedFileHandle.h`).

The coordinator's accepted dataless verdict surfaces Loading for a provider file as soon as the probe settles. A probe still running falls back to the half-second delay, as do local files and a remote streaming backend. Both paths match the open identifier and notify once. The player never repeats the filesystem probe on its queue, where a stalled stat would also block stop and the deadline.

**Progress is matched by the underlying open identifier, never by path or submitted-play identity.** A same-row replay changes submission identity but keeps the same `PlaybackRequestCoordinator.identifier`, transfer and timeout snapshot. A later retry of that URL gets a new identifier, so an older open's movement cannot extend it. `didBeginLoading:` carries the open identifier to the app, beside the request identifier in its identifier form. A rebind keeps the open identifier and takes the new play's request identifier. The app forwards `CloudTransferRegistry`'s movement for that file under it (`files/FileLoading/AGENTS.md`). The player accepts `noteOpenProgressForOpenRequestIdentifier:` only while both the pending request and the playback-open slot carry the identifier.

### Reading a file still downloading, or on a network mount

**A file a remote transfer is still writing opens as a stream, and a file on a network mount reads ahead.** How the handle reads both, how its reads wait, and how a wait is interrupted are `audio/Decode/AGENTS.md`'s. The coordinator opens a readable transfer's file this way and interrupts the open when its run is cancelled. The open's deadline, fed by the part file's growth, stops a stalled stream, and no longer applies once the handle is delivered. The voice bus interrupts the reads after it (the decode pool, above).

A persistent read error on bytes the open needs is retried, so that open fails at the open deadline as `VibeAudioErrorFileOpenTimedOut`. A dead server is then a wait, which the buffering hold and the stall below turn into a pause with `VibeAudioErrorConnectionLost`. A parked prefetch reads ahead too, and its progress counts against a stall only once the decoder reads it.

**A streaming MP3 with no count that fits the file opens on an estimated length** (`lengthIsEstimated`), settled once its reads reach the stream's end or its download completes. The player follows the estimate:

- **TRAP:** while the length is an estimate the player's window follows it (`republishEstimatedWindowOnQueue`, at every drain, a seek and a stall). It grows with the length and never shrinks, so the position never freezes at a short estimate, and a stall saves the position heard. Settled, the window is republished once more, exactly, with the optional `didSettleDurationOfTrack:`. The origin is untouched, so only the total moves.
- **TRAP:** nothing is refused against an estimate. `VibeCueWindow` keeps a cue end past it and runs a window to the file's end at least a frame past its start. A start past it (a stall's replay of audio heard past it) is kept, the settlement's window reaching it (`finishPlayOnQueueWithFile:`).

### Buffering and the stall

**A stream that falls behind buffers in place, and plays on once** (`updateBufferingOnQueue`, after every drain, from the current voice's snapshot; the render is untouched). The signal is the handle's own `waitingForBytes`, raised only while a read is blocked at the edge. The snapshot copies it with `decoding`. The voice is **held** when its decode waits with less than a quarter second buffered (`kBufferingGraceSeconds`). The grace is in audio, not time, so the hold's fade has frames and a link trickling in many short waits holds as surely as one that stops. The hold is the pause's own ramp and exact landing frame (a cut for a voice not yet heard). It is **released** once half a ring is buffered, the end is known, or the decoder has nothing left to wait for. A read waits for all it asks, so the decoder runs a chunk behind the download's edge.

The transport stays Playing. `isBuffering` is the flag, and the optional `didChangeBuffering:forTrack:` reports its edges for the current play. A held voice is not `outputAudioActive`. A user pause during a hold is an ordinary pause and ends it. A seek or track change ends it with its voice, and a play resumes the model. There is no start threshold: a stream's voice goes live at its usual chunk.

**The player decides when an app shows that it is buffering** (`bufferingNoticeShown`). The drain raises it once a hold has lasted `kWaitIndicatorDelaySeconds`, the delay a slow open waits too. So a shorter hold never flashes it. It ends at the first drain that finds the voice playing and not held, after a release or a re-voice. A stall and leaving Playing or the file end it too. **A new voice for the same file keeps it** (`publishState:…`). So a seek during a shown hold keeps it up. The old voice's hold ends with it. If the new voice holds, the notice stays. If the new voice plays, the next drain ends it. The optional `didChangeBufferingNotice:forTrack:` reports its edges for the current play. It is apart from `didChangeBuffering:forTrack:` because the two move apart and drive different work. The notice rises during a hold, and after a seek it can fall with no hold edge.

**A hold with no progress for the open deadline's span is a stall** (`AudioFileOpenTimeoutMath.h` over `openTimeouts`, snapshotted at the hold). Progress is the `bytesWritten` of the file the voice's decoder reads: its availability's `progressBytes`, from a transfer or a read-ahead. That is the voice's own file, or the queued successor once the decoder switched into it. A successor not yet read never counts, since its download would hide a stall of the file the voice waits on. A stall is Paused in place with `VibeAudioErrorConnectionLost`. The voice and its file are let go, and so is a park of the same file (a repeated track's). A transfer's claim then loses its last reader and is cancelled, and a read-ahead's thread ends with its handle. A stall is never a track end. The stall's park is the one Paused with no voice or file (`publishPausedWithoutVoiceOnQueueAtSeconds:`), with position and duration held for the getters. A seek moves its position. Resume replays the track from it through the ordinary play path, which fetches afresh. **TRAP: the replay runs in the resume's own queue turn** (`replayStalledTrackOnQueue`), under an identity minted only while the stalled play is still the newest submitted. Queued as a fresh `play:`, it would land behind a stop or play submitted after the resume, and undo it.

**`stop` unloads outright and fires no transport or track-end callback.** It must never drive auto-advance, and the caller owns its UI reset. It supersedes any in-flight open, so a Loading track never starts, and fades the voice to silence. `resetToStoppedStateOnQueue` handles stop and failures that unload playback. It retires the current voice, invalidates the open, drops the park and successor, and publishes Stopped. A stream stall or output restart failure can instead leave playback Paused. Track end and skip past the end both funnel through `didFinishPlaying:`.

## Live output levels

`levelsEnabled` installs the demand-driven meter, and `copyBandLevels:count:sequence:` reads its latest snapshot without the player queue or an allocation. The meter, its analysis, its publisher, its session traps, and its signal probe are `audio/Meter/AGENTS.md`'s. This is the player's side.

**The meter reads the final samples of the render, on both platforms.** It is the last stage of `VibeMasterBusRender` (`AudioMasterBus.h`) but the volume. It is after the bus, the varispeed and the FX returns, and before the volume and the debug silent output's zero. So an app's bars follow what reaches the device at full volume, wet tails included, and do not shrink with the volume. The meter needs no reconciling against the route, since it is a fixed stage of the render whether the FX segment is in or not.

**The meter is created at the first demand and kept.** `applyLevelMeterOnQueue` points the render at it and begins a publisher session while levels are wanted. It withdraws the pointer and ends the session otherwise, live and without waiting. The `AudioLevelPublisher` lives as long as the player, and each installation gets a new session. **The meter is freed only for a replacement**: the output's rate changing (`setMasterBusFormatOnQueue:`), the normalization mode changing (`debugSetEqualizerNormalizationMode:`), or the iOS media-services reset. It is freed once the render was seen outside it (`dropLevelMeterOnQueue`). A render stuck past the wait's bound keeps it alive until then.

**The demand is an app's indicators', not play intent.** Outside the beta signal probe, the meter is absent whenever nothing can draw it. An app counts the indicators that want levels (`equalizerLevelsWanted:`) and enables levels only while modeled output audio (`outputAudioActive`, below) and its own visibility rule also hold. Stopping an indicator balances demand at once. The meter is withdrawn too unless a beta signal probe holds it. A failed temporary installation is nil rather than inert, so a later output-start edge can retry.

**The debug silent output zeroes the output's buffers *after* the meter** (it is the volume stage's target of 0). So the bars are live with it, with or without hardware output (`testTheDebugSilentOutputZeroesAfterTheMeter`). Without hardware output, the pump drives the same render. That suits functional bar and counter checks, not audible-start-latency measurements. **The seam's two class flags, `debugSilentOutput` and `debugNoHardwareOutput`, are the app's to set** before it makes a player, from its own launch flags. The player reads no launch argument.

**The normalization mode lasts for the process and is never persisted.** `debugSetEqualizerNormalizationMode:` reconciles the player queue synchronously. Changing an active mode ends the publisher session and replaces the meter, with fresh history. Changing it while inactive stores the choice for the next meter.

**`outputAudioActive` is the app-facing liveness fact**: the output running, and either the current voice playing or a voice still fading. Loading intent alone is not, a buffering hold is not, and a paused voice is inactive the moment the pause is published. Its delegate edge is delivered on main only when the value changes. **TRAP: it is not "the output has stopped".** It excludes an FX tail on purpose, and no "tail is now silent" fact is modeled with a timer. That fact is `outputIdle`. It is NO from every output start attempt, a failed one included. It is YES again only when the idle stop has stopped the output, or the iOS media-services reset dropped the unit. On iOS the unit's queued stop has landed by then. On macOS it may still be queued. `audioPlayerOutputDidBecomeIdle:` announces it, and an iOS app releases its audio session on it (iOS/, below). A receiver reads the property at the edge, since a newer start may have overtaken it.

## Error text

**`VibeAudioError*` descriptions are for logs and are never localized.** An app maps `VibeAudioErrorCode` to the line it shows. The player reads no strings.

**Every error says whose it is** (`VibeAudioErrorKindOf`): the track's, the output's, or the reply that nothing is playing. The code alone cannot, since `VibeAudioErrorEngineStartFailed` covers both an output that would not start and a file that would not decode. The kind is stamped at construction under `kVibeAudioErrorKindKey`. Each code implies one, and `VibeAudioErrorOfKind` states a decode failure as the track's and a rebind that lost its file as the output's. The settlement's "unsupported format" is the output's: the bus it could not build is at the output's format, never the file's.

**An error about a play names its item and request identifier** (`kVibeAudioErrorTrackKey`, `kVibeAudioErrorRequestIdentifierKey`), beside the URL, so two rows of one file stay apart. Both `sendDelegateError` variants name the play current when they are called. **TRAP: a caller that resets the player first names the play before the reset** (`errorAboutCurrentPlayOnQueue:`), since a Stopped player has none. A Pause on a stopped player answers `VibeAudioErrorNotPlaying` with `kVibeAudioErrorPrecedingRequestIdentifierKey`, read and enqueued under the lock plays mint under. So it settles exactly the requests at or below it.

**The error domain is the app's, pushed once at launch.** `VibeAudioErrorSetDomain` takes it, in the shape of `ui/Shortcuts`' `VibeShortcutSetKeyNames`, and `VibeAudioErrorDomain()` reads it. The piece builds every play-path error under it, and an app's error rules compare against the same getter. An app may push its main bundle's identifier, which is the string `AudioError.m` held before the move. **An unset domain is a programmer error.** It asserts in a debug build and answers `@"VibeAudioErrorDomain"` in a release build. The tests and the minimal consumer push their own.

## Beta diagnostics

With `VIBE_VERBOSE_LOGGING=1` the player logs:

- `Timeline:` joins input and submission, queue admission, open settlement, the voice start, the first render (the live event and its start-of-consumption stamp), callback decisions and delivery, and the first position beyond the published playing position.
- `Phase:` brackets the player queue's side of a device rebind (macOS), output preparation, format confirmation and ownership. A bind, start or stop is the output unit's own `AudioOutputUnit:` line, timed on its queue.
- `Callback:` reports every bus event with the voice's consumed and underrun counts. A stopped voice's read interrupted at a stream's edge logs one line from its decode queue. **TRAP: that line reads the voice's identifier under the table lock**, since the drain clears it on the player queue while the turn is still on the decode queue.
- `Buffering:` is one line per episode as it ends: how long it held, how it ended (released, paused, retired, replaced, stalled) and the bytes that arrived meanwhile.
- `Stall:` reports main-thread, player-queue and output-render-clock stalls. It also reports IO cycles the output unit wrote as silence because the render returned an error (`outputDropouts`, cumulative, in `debugRenderCounts`, beside `renderMeanMicros` and `renderMaxMicros`).

The main-thread and queue watchers sample at 250 ms and every 500 ms after, six times at most. The player queue is sampled through its current pool thread (`THREAD_IDENTIFIER_INFO`). The render-clock check samples the output's IO thread once per stall, after more than 200 ms without progress. **An idle beta wakes nothing.** The main thread is watched by a run loop observer whose watchdog runs only while passes happen. The player queue's 100 ms ping ticks only while the output runs or a device phase is in flight (`performDiagnosticPhase:`). The render clock is read at every drain. On iOS a main-thread stall while the scene is not foreground-active is marked as such (`VibeStallWatchNoteSceneActive`), since iOS redraws a leaving app for the app-switcher snapshot.

**TRAP: the unified log truncates a message near 1 KB**, so a sample spans numbered `Stall stack:` lines. The app's frames are offsets into its executable. `atos -o <dSYM DWARF> -arch arm64 -l 0x100000000 <0x100000000 + offset>` names them, which is why each beta's dSYM is kept.

Every voice start, resume, seek, buffering release, gapless promotion, track-end crossfade, output format change, FX toggle, device rebind, iOS output recovery and late meter installation arms the bounded `Signal:` probe. What it captures is `audio/Meter/AGENTS.md`'s. It reads no file. On hardware each start also holds the meter itself (`_signalProbeWanted`) until its capture completes, so a hidden indicator still yields a measurement. The hold is released on the player queue, never from inside the meter's completion, and only by the newest request. The pump never holds it, since the hold needs `drivesOutputDeviceOnQueue`.

The player queue polls every 100 ms and emits one summary on first signal or expiry. Summaries keep the filename, play, voice, and start reason. Gapless keeps the owning play identifier but names the promoted file. Empty superseded summaries are omitted. The probe's origin is the pipeline's own clock at the start: the master bus's frames rendered plus the block in flight. Its cutoff, when a track change is still fading out, is the render that saw the last fading voice die. **TRAP: the varispeed emits the bus's frames late by its kernel's half-width.** That is 64 input frames, and ceil(64 × ratio) above a ratio of 1, which play in half / ratio output frames. So the cutoff is padded by `varispeedLatencyOnQueue`, which is 0 at zero pitch, where the render skips the converter. Unpadded, the probe reads the outgoing track's tail as the incoming one's first signal (`AudioPlayer+Diagnostics.m`).

## Mac/: the output devices

The player's two device categories: `AudioPlayer+Devices` and `AudioPlayer+BitPerfect`. They read the player's private state, so they sit with the player. The devices themselves are `audio/OutputDevices`: `AudioDevice`, `AudioDeviceManager`, `AudioDeviceEventLog`, `CoreAudioUtil`, and `OutputFormatRules.h`. Its `AGENTS.md` is the authority for the device list and its snapshot, the `HAL:` event log, the HAL reads and writes, and the format rules. `AudioPlayer+BitPerfect.h` imports `OutputFormatRules.h`, so a mac app that imports it reaches the format rules too. The map allows that edge. The report's type and its fold are the player's own, in that header, and the saved-device bind is `AudioPlayer+DevicesInternal.h`'s, since they read the player's state and the player is their only caller.

The player's side of an app's debug report is `bitPerfectReportDictionary` and `outputDeviceDiagnosticSnapshot`. The snapshot reads on the player queue, so a shipping caller invokes it off main.

**The player queue asks the device manager and never waits on it.** It calls `cachedOutputDevices`, `knowsOutputDeviceIsAbsent:`, and `outputDeviceForId:`, which never wait. **TRAP: absence in `outputDevices` is not removal** (`audio/OutputDevices/AGENTS.md`). So every decision that falls back to System Output and persists it asks `knowsOutputDeviceIsAbsent:`. Its callers are the player's device-list observer, `setOutputUnitDevice:`, and the `isAbsent:` blocks that retire the hog, listener, and format-restore obligations. The rate edge cannot wait for a snapshot, since a listener fires before the list catches up. It asks the device itself (`deviceIsConfirmedDead:`), off the player queue.

### AudioPlayer+Devices

All device management: resolution, switching, the rate the pipeline runs at, and parking or falling back when a device vanishes. Its `(PlatformOutput)` implementation owns the output unit's device half: binding it, starting it under exclusive access, feeding it the device's rate. `AudioPlayer+Pipeline` owns the platform-blind half. The unit itself, `AudioOutputUnit`, is shared with iOS, and everything device-shaped in it (the bind, the HAL latency reads) is `TARGET_OS_OSX`. `(DevicesInternal)` owns the device policy. It is declared in `AudioPlayer+DevicesInternal.h`, with the device ivars and bit-perfect's `(BitPerfectInternal)`. Only `AudioPlayerInternal.h` imports that header, under `TARGET_OS_OSX`. So it is on the player's private surface. Its public half, `(Devices)`, has its own header, which a mac app imports beside `AudioPlayer.h`.

#### The unit waits on the HAL so the player queue never does

Binding, configuring, starting and stopping each wait on a device's IO thread: hundreds of milliseconds on some interfaces, seconds for a waking DAC. The unit's methods are called on the player queue and record their effect at once. `deviceID`, `format` and `running` answer the state the unit is headed for. The HAL work runs on the unit's own serial queue in call order, so device changes and transport stay ordered and the player's rebind still commits synchronously.

- **A stop closes the gate before it returns**, so the proc is never called on a unit still at its previous device or format.
- **A start superseded by a later start or stop never runs** (`runGeneration`). The start opens the gate, then re-checks, so a racing stop always wins. **TRAP: a stop moves the generation before it closes the gate.** Closed first, a start could re-check the old generation after it and leave the gate open under a stopped unit.
- **A refusal arrives later.** A bind is refused at once only for a device the snapshot knows is gone (`setOutputUnitDevice:`, no HAL read). Any other refusal of a bind, configure or start reaches `failureHandler` and `outputUnitFailedOnQueue:`. Unless a later start or stop owns the unit, that stops the output, parks the current voice Paused and reports `EngineStartFailed` to the owning play. A refused bind reports `DeviceUnavailable`, and the unit forgets that device. Run generations come from one counter every unit shares, so another unit's never match. A missing unit still refuses synchronously.
- `running` is true from the request, so a start in flight counts as rendering.

**TRAP: the unit's own reads of its device are on its queue too.** Its latencies (after each bind, configure and start) and its channel map (after each landed bind and configure) are read there and answered from fields (`channelMap`, `presentationLatency`, `bufferLatency`; `AudioOutputUnit.h`). Read live, a hung device held the player queue 30 s per HAL call, and main with it through a debug dump.

**What the player queue still reads of a device is bounded.** The bound device's nominal rate after each bind (`followOutputDeviceRateOnQueue`), the audio path's device stage and the report's device reads each go through `CoreAudioUtil.performBoundedRead:`. That is one serial reads queue the caller waits on for at most 0.5 s. A late rate is followed when it comes, and while one read is overdue nothing waits. The bind and System Output's default ask the manager's snapshot, never the HAL. **Still read unbounded on the player queue**: the system default once, when the unit is created, and bit-perfect's own reads and writes, which the mode blocks at by design (below).

**TRAP: a device write on the player queue must `waitUntilIdle` first.** The stop it follows is only queued, and a hogged device's format written under a running output strands its next start with error 35. The physical-format write and confirmation (prepare and restore, one funnel) and a change of hog ownership each wait. So bit-perfect and exclusive output block at those edges and nowhere else. Teardown stops the unit and waits too, so no queued start can pull a freed master bus.

**TRAP: AUHAL can reinitialize before its device-format notification and keep the old converter.** The device's confirmed rate can precede the unit's notification, with its converter still at 48 → 44.1 kHz. So `AudioOutputUnit.halConfigureFormat:` creates a fresh HALOutput component, binds the current device, then sets the client format and initializes. It keeps the wrapper, queue, render gate and run generations, so stop and start ordering is unchanged. RemoteIO is not recreated for a format change.

#### Resolving the saved device

The player's async init asks the manager to resolve the saved device without blocking the player queue. `resolveOutputDeviceForUID:modelUID:name:completion:` waits for the first successful snapshot and matches **by device UID, then model UID, then name** (`audio/OutputDevices/AGENTS.md`, which carries the USB location trap). The player starts on System Output, bound to the system default at its rate. While that device lives, the unit moves only when a rebind moves it. Nothing follows the system default on its own. An unmatched saved preference stays pending during ordinary playback. With bit-perfect armed, a published absence disables the mode and commits System Output. A match is committed when the synchronous rebuild accepts the selection. The HAL bind runs later on the output unit's queue and may still fail. If playback wins the race, the intent stays pending for the next eligible edge. Until the rebuild accepts a selection, `currentlyRequestedAudioDeviceId` stays `-1` and the saved preference stays pending.

**Where that deferred bind may land is `VibeCanBindSavedOutputDevice`: whenever nothing is audible.** That is Stopped, Loading while the output is not running, or a pause whose fade has settled. Loading is included because a launch by opening a file starts an open within milliseconds of the async init. Without it the *first* track would play through the system default. **TRAP: an ordinary mid-session track change is also Loading**, with the outgoing voice still fading on a running output. Rebinding there would stop the output under that fade and click, which is why the rule checks the output. Playing is excluded, since a failed bind there tears down live playback. **A pause is not excluded.** A vanished device's playback continues on System Output with its identity pending, and a pause is the first silent moment that can move it back. The rebuild restores a paused track as Paused, and the pause verb calls the resolver.

**TRAP: returning devices resolve synchronously against `cachedOutputDevices`.** An asynchronous answer can lose to a local open that moves Loading to Playing and makes the bind ineligible. Only initial discovery waits, and its callback re-reads the current preference and snapshot so it cannot revive an older choice. **TRAP: hold `_pendingSavedDeviceLookupInFlight` across every bind, cached resolutions included.** A refused bind publishes Stopped, and its reset must not queue another attempt. Other resets defer resolution to the next queue turn, after the enclosing rollback. An absent result with bit-perfect off does nothing, keeping the intent without new lookups.

`didChangeOutputDevice:` is sent on **every** settled mutation, not only when the id moved. A refused selection re-announces the retained choice, which repairs a UID an app's settings reset cleared. A still-pending saved preference is kept, not overwritten with the temporary binding. The delegate persists the choice, and is idempotent. Suppressing an unchanged value would leave a path that made the app's settings and the binding disagree with no call to resynchronize them.

A vanished device and an absent launch preference share the pending identity slot. Falling back disables unavailable modes and follows System Output without forgetting that identity, so a later notification or silent transport edge can re-adopt it. Every `-1` announcement derives its involuntary reason from the pending slot and passes it to the delegate by value, captured before the hop to main. Only an explicit System Output selection or a successful concrete selection clears pending intent.

**System Output's default is the snapshot's `isSystemDefault` device, never a HAL read on the player queue.** The manager refreshes before either observer fires. A default read there waits behind a busy `coreaudiod` and holds every transport command. No snapshot yet, or devices with none the default, is unknown, not absence: macOS names no default for a moment while it moves it. Playback is kept, one coalesced delayed bind is tried, then it waits for a notification. Only a published snapshot with no output device parks playback.

#### Device edges

**The edges are the manager's two observers, the bound device's listener in every mode (its nominal rate and its hog owner), and, while a bit-perfect device is prepared, that device's one listener.**

- The system default moving reaches `setOutputDeviceOnQueue:-1` when System Output is the policy, and its rebind moves the unit.
- The device list changing asks `knowsOutputDeviceIsAbsent:` and falls back.
- A rate other than the pipeline's on the bound device, not confirmed dead, is another process moving it (Audio MIDI Setup, a DAW, a loopback verifier). Both are read on `performBoundedRead:`'s queue. `configureOutputDeviceOnQueue:` rebinds in place, following the rate and re-voicing. **TRAP: a hosted unit left at the old rate renders nothing.**
- The prepared device's listener sees the same rate event, and there the prepare sets the mode's format back instead.

The player's own format writes arrive with the pipeline already at the rate, a no-op. The hosted unit never stops on its own. When its device vanishes (unplug, a `coreaudiod` restart, which renumbers every device), AUHAL moves it to the system default and keeps pulling, and the device-list observer's rebind makes that explicit. So macOS has no configuration-change recovery.

**Another app taking the bound device parks playback and says so.** **TRAP: a foreign hog halts the unit's IO without stopping it** (no `IsRunning` change), so the transport would read Playing over a frozen position. The listener reads the hog owner in the same bounded read as the rate, and so does the read after every bind. `_boundDeviceHeldElsewhere` records it. Taken under Playing, `followBoundDevice:toRate:heldElsewhere:` parks the voice as a lost device is parked and reports `VibeAudioErrorDeviceInUse`. Under any other state it stops the output, so a Loading settlement cannot start into the frozen device. While the flag stands, `startOutputUnitOnQueueWithError:` refuses every start with the same error. A resume stays Paused, and a new play lands Stopped. **The refusal is policy, not the HAL's**: a unit started under a foreign hog plays, and would mix into the output another app asked to have alone (`CoreAudioUtil.h`). The release clears the flag and nothing else. Playback never restarts on its own.

**A rebind stops the output and keeps the current voice.** The stop kills every fading voice. The current voice keeps its ring and gain, and a restart continues it in place. Only when the source segment must be rebuilt (the mode or the output's format changed) does the voice die with it, and the rebind starts a new one at the retained intent. Either way the successor is re-queued after. Selecting the active device still rebuilds when bit-perfect is wanted but the device is not prepared, so a newly eligible selection prepares the current track.

**Losing an output parks the current voice where it is.** `parkPlaybackForMissingOutputDeviceOnQueue` stops the output, killing every fading voice, and pauses the current voice with a cut that lands at the first render after any restart. No schedule survives to fire a false track end. A failed re-adoption at natural end cannot clear the already-captured finish settlement. A track end captures its track and submission before optional device recovery, since a failed bind resets the active identifier.

### Bit-perfect output

`AudioPlayer.setBitPerfectOutput:exclusiveOutput:enableFX:allowAnyDevice:` requests an output path that preserves decoded samples. The report identifies any format, channel or volume mismatch. The mode is `AudioPlayer+BitPerfect`. Its public half, `(BitPerfect)`, is the setter and the report, in its own header, which a mac app imports beside `AudioPlayer.h`. The queue-side mechanism is `(BitPerfectInternal)`, declared in `AudioPlayer+DevicesInternal.h`.

**Declick** decides what the mode does at a transport edge. On, each play, seek, pause, resume, stop or track change gets the ≤10 ms declick ramp, and every other frame, a gapless boundary included, is unchanged. Off, the edge is a cut that leaves every sample untouched. It reaches the player as `AudioPlayer.declick`, with no rebuild. `effectiveCrossfadeMilliseconds` clamps the crossfade to the declick minimum. Declick off removes transport gain ramps. The player's volume still applies and reports VolumeScaled below full. A loopback verifier turns Declick off around its captures, which compare from the first frame.

**Both modes belong to the destination UID.** An app remembers only enabled modes, keeping entries while devices are unplugged. It supplies them through `audioPlayer:outputModesForDeviceUID:bitPerfectOutput:exclusiveOutput:`, a read-only query safe from main and the player queue. Explicit selection and saved-device resolution share `selectOutputDeviceOnQueue:`. It reads the destination's modes before the one rebuild, and restores the previous flags if the switch commits nothing.

- **TRAP: a failed rebuild may already have rewired or prepared the destination.** After restoring the flags, a Stopped player stops the output and takes `leaveOutputDeviceOnQueue`, retiring the destination's format, listeners and hog obligations. A player still holding its track keeps it.
- **TRAP: a name fallback can resolve different hardware.** Read the destination's own modes before preparing or hogging it, never the missing device's. Pushing modes after a bind would first rewrite the format of, and possibly hog, a device whose mode is off.
- **The one exception is a model-UID match under a new device UID**: the same model on another USB port. Only when the destination has no saved modes does `selectSavedOutputDeviceOnQueue:` read the old UID's (`_modesUIDForNextSelection`). `carriedModesFromUID:` carries that decision by value into the delegate callback. The app persists only that carry, on main. A manual selection never infers a carry. The carry copies, so the old port keeps its entry, and never overwrites the destination's own modes. Two identical units of one model share modes, because the OS cannot tell them apart.
- Until the main-thread callback has saved a carry, it stays readable through `_unpersistedOutputModeSources`, under `_stateLock`. Queued FX edits resolve it transitively, consecutive port changes included. The callback clears only its own entry. Never call main synchronously from the player queue to persist a carry.
- Queued mode and FX edits re-read the queue's current UID (or the pending saved UID), so a snapshot submitted behind a switch cannot overwrite the destination's preferences. System Output has no UID and reads off. If its default read fails, its committed mode change still rebuilds the current binding: an unknown read keeps playback, while confirmed absence parks it.
- The public selection completion runs on main after the device callback, failed switches included, so an app can release its mode-edit guard.
- `setOutputDeviceOnQueue:` also rebuilds when only the standing graph disagrees with the flags. A switch from a bit-perfect device to System Output may stay on the same hardware but must restore its format and FX route.

The format and eligibility decisions are `OutputFormatRules.h`'s. The raw HAL reads and writes are `CoreAudioUtil`'s. Vibe's loopback oracle (`scripts/test/verify-bit-perfect.swift`) measures 16-bit, 24-bit and float32 WAVs at every rate from 44.1 to 192 kHz, and a 48 kHz 24-bit FLAC, ALAC and AIFF, sample-exact.

**Exclusive output is a separate opt-in**, off by default. Bit-perfect, exclusive output and the saved FX preference land on the player queue in one setter. They use the same-device rebuild, which keeps the track, position and pause state, reading `getPlaybackIntent:forTrack:` before stopping the output. Changed settings stop the output before changing ownership. Identical settings return without rebuilding. An exclusive preference changed while bit-perfect is off is saved without touching the graph. Disabling exclusivity releases the device without restoring its format. Disabling bit-perfect restores the format and releases it through `leaveOutputDeviceOnQueue`, inside the rebuild. While saved-device discovery is pending, turning bit-perfect off still works on the current binding. An in-flight open also rebinds the warm output without consuming the request, so its settlement starts with the latest preference. The saved exclusive preference survives a bit-perfect toggle, but acts only while bit-perfect is on. With an eligible device prepared, it *is* `hogWanted`.

**Off is dormant.** Format preparation and reporting gate on `_bitPerfectWanted`. Disabling publishes an Off report and removes the prepared-device listener after restoring the device. Ordinary playback still reads the bound device's rate and hog owner. A failed restore, listener removal or release is kept and retried at the next cleanup edge, never by polling. Listener removal retries once and keeps its handle on failure, refusing a second device until it succeeds.

**The format rides the play settlement; the hog rides the running output.** `prepareOutputOnQueueForFile:` runs in `finishPlayOnQueueWithFile:…` after the request is consumed and before the source segment is reconciled. It also runs in `rebindOutputOnQueueToDevice:`, which `configureOutputDeviceOnQueue:` calls. It reads the bound device's first output stream once and applies two rules:

- **The rate rule**: exact, else the smallest integer multiple, else untouched. It scans PCM offers carrying every source channel and continuous ranges, including 3x, 6x and ratios above 16x. Encoded-only rates cannot hide a usable PCM multiple.
- **The depth rule**: the widest integer depth the device offers, never one below the source's, else the widest float format. Float and lossy sources take the float format first, since what reaches the device is a float32 decode. The bits added to an integer source are zero. A sample the player changes (its volume, a declick) is then rounded at the widest depth, never at 16 bits without dither. One depth for every integer source also lets a 16-bit and a 24-bit track at one rate share a format. Moving between them needs no switch, and a splice between them can arm. The chooser uses the device's advertised formats.

It rejects physical formats with fewer channels than the source. When the device's format or the bus's rate differs, it stops the output itself (both callers guarantee nothing is audible). It writes one `kAudioStreamPropertyPhysicalFormat` and polls for confirmation with a 1.5 s deadline. Individual HAL calls can block longer. It then **brings the pipeline to the device's rate** through `applyOutputRateOnQueue:`. **TRAP: an accepted format write precedes the nominal rate.** `setOutputFormatOnQueue:stream:device:` confirms every physical-format field but the reserved word, and the nominal rate, before the pipeline follows. Matching rate, depth and channels alone cannot confirm a restore with different packing or byte order. Preparation and restoration share it.

`acquireExclusiveOutputOnQueue` runs in `startOutputUnitOnQueueWithError:`, before the unit starts. `releaseExclusiveOutputOnQueue` runs after the idle stop's output stop, before a rebind, on mode off and at quit. `CoreAudioUtil.supportsHogModeForDeviceID:` checks that the hog property exists and is writable, for physical and virtual devices alike. That is a capability check, and the owner read-back decides success. Loopback recording requires exclusive output off.

**TRAP: setting `kAudioDevicePropertyHogMode` ignores the value and toggles ownership.** So `setHogOwnedByThisProcess:` reads first and writes only when the owner has to change. "Owned by this process" is the whole state, and a release while another process holds it is already true. A sandboxed app needs no entitlement for it. `_hoggedDeviceID` records the obligation before the take, since a successful write followed by a failed read-back may own the device. Release retries once, then keeps that slot until a release succeeds or the manager confirms the device gone. A second device cannot overwrite it. The report reads the prepared device's actual owner.

**Taking the system default output device moves the default; the hosted unit stays.** `coreaudiod` answers the hog by moving the default to another device. A HALOutput unit bound to the device stays bound through the take. So `acquireExclusiveOutputOnQueue` returns once the hog is confirmed. `configureOutputDeviceOnQueue:` keeps the hog, the format slot and the prepared device on a rebuild of the device already held.

**The pipeline runs at the bound device's rate, in every mode.** The bus, the varispeed, the FX chain and the unit all run at the rate `applyOutputRateOnQueue:` last applied. `followOutputDeviceRateOnQueue` reads the nominal rate after every bind, bounded. The prepare applies the rate its format write settled on. Any file-rate conversion stays in the voice decoder. The master bus and output unit share one rate. `applyOutputRateOnQueue:` stops the output, reconfigures the unit and sets the master bus's format, which re-hosts a connected FX chain and replaces the meter. **TRAP: the source segment stays at the old rate for the caller to reconcile**, which re-voices when it rebuilds. Rebuilt inside `applyOutputRateOnQueue:`, the caller's reconcile would find the bus already at the rate and never start the replacement voice: silence while Playing. A format the HAL refuses fails the next start, which parks the voice through the refusal path above. `outputNeedsSwitchOnQueueForFile:` still counts a bus rate that differs from the chosen one as a switch, for a rate moved by another process before its listener landed.

**A switching settlement stops the output before changing the device format.** An unreadable format is unknown compatibility and refuses a gapless successor. The settlement rejects an obsolete open identifier before any device query. A format switch kills every fading voice. Bit-perfect fades nothing but its declicks, so a cut there costs only a declick.

**The chain is pruned by the switch, not the device.** With the mode on, `ensureSourceSegmentOnQueueRebuilt:` (`AudioPlayer+Pipeline`) builds the bus at the output's format, which is the file's rate once the prepare moved the device there. It has no varispeed stage. The ordinary varispeed also bypasses its kernel at zero pitch. The FX segment is disconnected before preparation, and leaving bit-perfect reconnects it when FX is enabled. Every settlement reconciles the segment right before the voice starts, so a toggle during an open lands on the chain the mode wants. The device rebind reconciles it on the current track, which is how both mode toggles rebuild the current track in place.

**Restore is one slot.** The first format change to a device in a run remembers the device, its stream and its format. Mode off, a switch to another device and `prepareForTermination` retry the write once. They clear the slot only after success or a confirmed removal. `leaveOutputDeviceOnQueue` restores, forgets the prepared device and releases the hog, in that order. A failed restore stays in the slot for the next leave, prepare or quit. Another device may play at its existing format but cannot change format until then. `CoreAudioUtil.releaseDeviceObligation:attempt:isAbsent:` is the shared retry loop for restore and release. A vanished device takes the off path: `abandonBitPerfectForVanishedDeviceOnQueue` drops the mode, restores and releases before the fallback binds System Output. The device's stored modes survive.

**Eligibility is an allowlist of transports** (`VibeBitPerfectDeviceEligible`): built-in, PCI, USB, FireWire, Thunderbolt, HDMI, DisplayPort, AVB and virtual. Bluetooth, AirPlay, Continuity, the Remote types, aggregates and Unknown are out, and so is anything Apple adds until argued in. The System Output policy is the absence of a chosen device, and the current default device is judged like any other. `allowAnyDevice` bypasses the allowlist for testing. It changes eligibility, not the device's capabilities, and changing it rebuilds an enabled mode. An app's switch, menu and report all read the one rule. **The device the mechanism drives is the requested id, or the destination while a switch is in flight** (`_rebindDeviceID`, set during `configureOutputDeviceOnQueue:`). The switch prepares and hogs its destination before `setOutputDeviceOnQueue:` commits the id, since a failed switch must not commit. It is never the unit's own device, which names the one being left.

**The report** (`VibeBitPerfectReport`, `bitPerfectReport`) carries the status and every fold input. `VibeBitPerfectFold` names the first reason the output is not bit-perfect, in a fixed priority order. It also carries the file's depth (`sourceBits`). The device runs at its widest integer depth, so its own depth says nothing about the file. Each publication computes it from its owners: the mode, the pipeline, the chosen device, the hog, the current file's source format (so a gapless promote reports the promoted file), the prepared physical format, the HAL's volume, balance and mute, and `AudioPlayer.volume`. A player volume below full reports VolumeScaled. Its setter refolds the report with no device read (`refoldBitPerfectReportForPlayerVolumeOnQueue:`), since a slider drag lands there every tick.

- `formatConfirmed` compares the live format against what the prepare asked (`_prepared*`). It also requires no varispeed, the FX disconnected, the unit bound to that device, the bus and unit at the physical rate, successful format and control reads, and the device listener installed. A device at the right rate cannot confirm a pipeline that still resamples.
- An unconfirmed output reports SwitchFailed before a rate mismatch can report RateUnsupported. A prepared fallback rate still reports RateUnsupported.
- `channelsMatch` requires the source, the decoder, the bus and the unit's input to carry the source's channel count. The bus is stereo, so a wider file reports ChannelConversion. The unit's `ChannelMap` must route those channels in order into the prepared stream, every other hardware output silent. So wider interfaces qualify without a downmix, swapped pair, duplicate output or unknown map.
- Mute has its own status even at full volume. Off-center balance or driver pan is VolumeScaled even at 100%. The reader checks the driver's main volume and mute and every source channel in the prepared stream. Missing optional controls mean unity, center and unmuted. Unreadable controls cannot confirm the output.
- `depthOK` rejects non-PCM formats and asks whether the file's processing format carries the source as well as the device's format does. The handle decodes to float32, whose significand is 24 bits, so a 32-bit integer source is never Active.

The publication rides existing edges: `refreshOutputAudioActiveOnQueue` (every state publication and fade completion), the end of a device switch, the two hog edges and the mode toggle. It also rides one HAL listener on the prepared device: its output properties, every element, and its nominal rate. A changed report is announced through `audioPlayerDidChangeBitPerfectReport:` on main, the one edge an app redraws its status from. **A publication's device reads are one bounded read, and the output controls are cached.** The physical format, the hog owner, the starting channel and any uncached controls are read together through `performBoundedRead:`. A device that does not answer in 0.5 s reads as unconfirmed. The volume, balance and mute reads (ten-odd, about 20 ms per track change on one USB interface) are kept per prepared device and stream while `_outputLevelListener` is registered. That listener clears the cache before it republishes, a fresh registration clears it too, and a failed read is never kept. A Loading publication asks for no channels and reuses the last track's reading. Beta builds log each fresh read and any publication whose device reads took 2 ms or more.

**The gapless splice is gated on the mode too.** A queued successor keeps the device's format, so `maybeArmSuccessorOnQueue` asks `outputNeedsSwitchOnQueueForFile:` (and `VibePCMFormatsMatch` on the two processing formats). A next file that wants another format, its channel order included, takes the settlement, which switches the device or rebuilds the bus. The idle stop waits 6 s in both modes, and longer while an FX tail rings.

**Termination.** An app detaches the delegate on main first. `prepareForTermination` closes admission and uses `stopOnQueue` to retire the voice and cancel the open, the park and the successor. It then stops the output and restores and releases device obligations. Discovery, notifications, playback and prefetch cannot restart it during the app's termination.

## iOS/: output recovery

What the player does when the system moves the audio out from under the output. The render is pulled by the same `AudioOutputUnit` on both platforms, a RemoteIO unit here. This half implements the shared `(PlatformOutput)` declaration in `AudioPlayerInternal.h` for iOS. `(Recovery)` receives the session controller's recovery verdicts.

The session itself is `audio/OutputDevices`: `AudioSessionController`, `AudioSessionRecoveryRules.h`, and `OutputRouteRules.h`. Its `AGENTS.md` is the authority for activation and release, the four events and their verdicts, and the route rules. An iOS app is the controller's delegate. It maps each verdict onto the player's public API.

**The session is released once the player's output has actually stopped.** `AudioPlayer.outputIdle` answers the delegate's `audioSessionOutputIsIdle:`. The player's idle edge asks again (`audioPlayerOutputDidBecomeIdle:` → `deactivateIfIdle`). The idle stop is the player's and waits out an FX tail, which no timer of the session's can know. **TRAP: the idle stop's unit stop is only queued**, so `releaseIdleOutputUnitOnQueue` waits the unit's queue out before idle is published.

**A buffering hold keeps the output running, by construction.** The hold is the pause's ramp with the transport left Playing. The idle stop is armed only on a pause or stop, and stops nothing unless the state is still Paused or Stopped. So RemoteIO keeps pulling silence and the session stays active while a stream buffers. A backgrounded app keeps the audio that keeps it from suspension, and the download with it. The stall is a real pause, so its idle stop follows six seconds later and the session releases.

**No output unit exists before the first play.** Launch sets the pipeline's format from the session's rate. FX hosting follows its enabled connection and claims no output. The RemoteIO unit is made at the first output start, after the play activated the session. A unit made at launch would take the session's default SoloAmbient category, which is not mixable and stops whatever else the device is playing.

**RemoteIO keeps running across a route change that brings a device in**, converting to the new hardware rate itself. **iOS can stop the unit itself after a route loses its device.** That stop reaches the player through the system-stop path below, after the route-loss verdict has already paused. So the unit is not guaranteed to survive a route change. For a device coming in, the recovery verdict has the pipeline follow the route's rate, so the bus's conversion stays the only one.

**A pause verdict during Loading parks the landing** rather than being dropped. The player's `pause`/`resume` update the pending request to the requested state, so duplicate system verdicts are no-ops, not toggles.

### AudioPlayer+Recovery

The player's output-recovery category. `AudioPlayerInternal.h` imports its header on iOS, where the mac imports `AudioPlayer+DevicesInternal.h`. It lives in `iOS/` so the mac target never sees the API. An iOS app calls it for `AudioSessionController`'s verdicts, and calls `recoverOutput` after a remote Play command's resume.

**The system stops the unit under the app, and says so only through the unit.** An interruption stops RemoteIO without asking. `AudioOutputUnit`'s `IsRunning` listener reports a stop it sees with the gate open (the player's own stops close the gate first) through `failureHandler` without an error. **TRAP:** RemoteIO reports on a thread of its own, and removing its listener does not wait for a report in flight. So the listener's refCon is a token the unit is looked up by, weakly, and the reference that lookup takes is dropped on the unit's queue, never inside RemoteIO's callback (`AudioOutputUnit.m`). The player stops its output at that edge (`outputUnitFailedOnQueue:`), so the liveness fold and the drain timer follow at once and the next start is an ordinary one. What the transport does is the session verdict's. **TRAP: the stop itself never pauses.** It can land a millisecond before its interruption's Began, whose was-playing the Ended resume depends on. **A stop no verdict follows pauses after a second.** iOS stops the unit seconds before it delivers a media-services reset, with no interruption. Playing would otherwise be published over a dead output until the notification came.

- `recoverOutput` is for a playing voice only, since every start follows the route itself. It follows the route's rate, then restarts a unit the system stopped. A route at **another sample rate** is followed through `followOutputFormatOnQueue:` (`AudioPlayer+Pipeline.h`). The unit and the bus are rebuilt at it, with the track kept at its position and state, so RemoteIO converts nothing. Otherwise a stopped unit under a Playing voice restarts in place: the voice kept its ring and gain, so nothing is rescheduled. **The same follow runs before every output start** (`followOutputRateOnQueue`), because a route loss or an interruption blocks recovery until an explicit activation. Without it the next start would run on the stale rate with RemoteIO resampling. A restart with no unit to make parks the track Paused (`didPausePlaying:`). A start the unit refuses later parks it too and reports the error (`outputUnitFailedOnQueue:`).
- `beginMediaServicesResetWithCompletion:`: **every audio object is dead per Apple's contract**, so the player drops them without messaging them. `dropOutputBoundStateOnQueue` closes the master bus's gate and retires the bus, meter and FX hosting through `afterRenderLeavesOnQueue:`. It marks the FX units dead even while bypassed, and marks `_outputUnit` dead and releases it. A late failure from it never matches the next unit's run generation. A dead unit closes its gate and supersedes any queued start. Its queued configure and stop, and its dealloc, no longer message the instance, and the dealloc only disposes it. `createOutputOnQueue`, shared with init, then rebuilds the launch shape. **TRAP:** the reset is called synchronously on the notification thread. Reset receipt and play submission each enqueue under the same state lock, so a play received after the reset runs on the new output (`AudioPlayer+Recovery.m`). The recovery position is read from the voice's counter before the bus is dropped. Its main-thread completion runs only after Stopped is authoritative and only if no newer play superseded the reset. The app then publishes that state and re-parks the captured track.

**Verifying needs a real device.** The simulator exercises none of this faithfully: interruptions (ended with and without `ShouldResume`), route changes (headphone and Bluetooth plug and unplug, playing and paused, with a rate follow), media-services reset, background audio past lock, and whether a cold launch leaves another app's audio playing. Check delayed system stops as well as the notification itself. Every edge logs, so a device run is read from its log: the unit's starts, stops and system stops, and each verdict the app passes on. A buffering hold on a locked screen shows its `Buffering:` line's held time with the transport still Playing, and no `AudioOutputUnit: stop` line.

## The manual render pump

**`VibeManualRenderPump` stands in for the output unit.** The player hands it the pipeline's render, and the pump pulls it. It is two things. Frame-driven, a test calls `debugRenderFrames:` and gets exactly those frames, and the pump decodes the bus inline before every slice and drains it after, so a voice is live before the first slice that could render it. Automatic, it renders at real-time pace on a timer, which is the seam's no-hardware output. Voice ramps, FX sweeps and the idle stop run their production algorithms on its clock. File opens and delegate delivery keep their real queues. It lives with the player, since it fakes the player's output (the plan's rule 8). It compiles in every configuration and wraps its body in `#if DEBUG`, as the seam does.

`AudioPlayer+Debug.h` is the seam: `initForManualRendering:enableFX:automatic:delegate:`, the render and capture, the starved and held decoder, the held render, the pipeline's counters, the rate a test moves under the pump, and the two output flags (`debugNoHardwareOutput`, `debugSilentOutput`). A player made for manual rendering attaches the pump in place of the output unit, before any voice exists, and binds no device. The pump proves the software path, not DAC samples, hardware negotiation, exclusivity or iOS session recovery.

## Tests

`Tests/audio/Player/` holds the player's tests that write their own fixtures. `PlayerTests` runs them on macOS, with the headermap off. It defines `DEBUG` in every configuration, since they drive the seam and the pump.

- `AudioVoiceBusTests` tests the voice bus host-less: the tests own the output buffers and call `VibeVoiceBusRender` with inline decoding, so every frame is compared against its file. `AudioVoiceBusPoolTests` covers starvation, kills and the voice pool, the decoders' hand-off of files and converters, and the races between the render, the drain and a decode turn. Their harness is `AudioVoiceBusTestCase`, which runs no tests.
- `ResamplerQualityTests` holds the resampler to its bounds through the voice bus, against `VibeReferenceResample`.
- `AudioPlayerReparkTests` plays the whole player on the pump over fixtures whose every sample names its file and frame. It re-parks a successor the decoder already reads, at distances across the read-ahead window, between the render that crosses the boundary and the drain that reports it, and after, and checks the frame after the boundary.
- `AudioFXChainTests` hosts the FX chain alone and calls `VibeFXChainRender` through the pump's frame-driven clock.
- `AudioOutputUnitTests` covers the unit's render callback, its counters, and its configure, start and stop on its own queue.
- `AudioPrefetchRulesTests`, `PlaybackDeliveryRulesTests`, `PlaybackIntentTests`, and `PlaybackRequestCoordinatorTests` cover the rules and the coordinator. `Mac/AudioPlayerBitPerfectRulesTests` covers the report's fold and the saved-device bind. `AudioErrorTests` covers the error vocabulary, and pushes the bundle's domain at image load, as an app does at launch.

The test track (`Tests/Support/VibeTestTrack`) is their playable item: a file and its window, a fresh object per call. The reference conversion, the tone fit and the device's offered format are `Tests/Support/AudioReferenceFixtures.h`, beside `AudioFileFixtures.h`. The minimal consumer plays a queue of its own rows through a player on the pump: two rows of one WAV of a ramp, then a CUE window of another. Its delegate parks the queue's successor at each start and each advance. It reads every frame back exactly, and checks each callback hands back the row it queued.

**The render suite is `Render/`, and an app's test target runs it.** It plays the whole player through the pump over an app's generated fixtures, which it finds where `VIBE_AUDIO_FIXTURES` points. Nothing here generates them, so `PlayerTests` does not compile `Render/`. Vibe's `VibeAudioTests` compiles it from the submodule (`make test-audio`), with the voice bus, the varispeed and the FX at `-O2` for its long PCM comparisons. `AudioPlayerRenderTests` is its base class, which runs no tests. Each topic is a subclass. Vibe keeps one topic, `AudioPlayerRenderLinkTests`, which plays a link through Vibe's own link store. Vibe's `Tests/AGENTS.md` describes the oracle and the coverage.

**TRAP: the render suite swizzles OutputDevices' methods by selector.** The device, pipeline and output topics replace `AudioDeviceManager.sharedInstance` and `CoreAudioUtil`'s `systemDefaultOutputDeviceID`, `readSystemDefaultOutputDeviceID:`, `deviceIsConfirmedDead:`, and `readNominalSampleRate:forDeviceID:`. Nothing here compiles that suite. So a rename of any of them in `audio/OutputDevices` passes this repo's checks and breaks an app's render suite. Rename the swizzle with the method. Each swizzle carries the same `TRAP:`.

**A bounded wait is a hang guard or a gate.** A wait for what must happen uses `VIBE_TEST_HANG_TIMEOUT`. A gate the test releases itself uses `VIBE_TEST_GATE_TIMEOUT`, which outlasts the guards it holds across. The bundle defines both. **Threading changes run under ThreadSanitizer**: the voice bus tests and the render suite, with `-enableThreadSanitizer YES`. A test's own cross-thread flag must be atomic, and so must a swizzle's saved original IMP when the swizzled method can run while the swizzle installs.
